# Запуск notebook-сервера и интерфейс браузера

> **Модуль 6 · Урок 3** | Время: ~15 мин

## Что происходит при запуске

Jupyter Notebook — это **клиент-серверное приложение**. Команда `jupyter notebook` запускает локальный веб-сервер (по умолчанию на порту 8888), который принимает соединения от браузера и отдаёт интерфейс для работы с ноутбуками.

```
Терминал: jupyter notebook
    ↓
Сервер слушает localhost:8888
    ↓
Браузер открывает http://localhost:8888/...
    ↓
Интерфейс: файловый менеджер, открытые ноутбуки
```

Сервер и браузер работают на одной машине — вы обращаетесь к localhost. Пока сервер запущен, все изменения в ноутбуках сохраняются на диск.

## Запуск сервера

В активированном venv выполните:

```bash
jupyter notebook
```

Команда `jupyter notebook` запускает сервер и обычно автоматически открывает браузер с URL вида `http://localhost:8888/?token=...`. Токен — это секретный ключ для доступа; в локальной разработке его можно игнорировать, но при удалённом доступе он обязателен.

**Ожидаемый вывод в терминале:**

```
[I 2024-01-15 10:00:00.000 ServerApp] Jupyter Server is running at:
[I 2024-01-15 10:00:00.000 ServerApp] http://localhost:8888/tree?token=...
[I 2024-01-15 10:00:00.000 ServerApp] or http://127.0.0.1:8888/tree?token=...
[I 2024-01-15 10:00:00.000 ServerApp] To access the server, open this file in a browser:
...
```

## Полезные опции запуска

| Опция | Описание |
|-------|----------|
| `jupyter notebook --port 8889` | Запуск на порту 8889 (если 8888 занят). |
| `jupyter notebook --no-browser` | Не открывать браузер автоматически — удобно при SSH. |
| `jupyter notebook --notebook-dir ~/projects` | Корневая директория файлового менеджера (по умолчанию — текущая). |

Пример для удалённой машины:

```bash
jupyter notebook --no-browser --port 8889
```

Затем на локальной машине проброс порта (`ssh -L 8889:localhost:8889 user@remote`) и открытие `http://localhost:8889` в браузере с token из вывода сервера.

## Интерфейс: файловый менеджер (Dashboard)

После открытия браузера вы видите **файловый менеджер (Dashboard)** — список файлов и папок в директории запуска. Здесь можно:

- **New → Python 3 (ipykernel)** — создать новый ноутбук.
- Клик по `.ipynb` — открыть существующий ноутбук.
- Переименовать и удалить файлы (через правую кнопку мыши или кнопки в интерфейсе).
- Создать папки, загрузить файлы.

Каждый открытый ноутбук — отдельная вкладка в браузере.

## Остановка сервера

Сервер работает, пока в терминале идёт вывод логов. Чтобы остановить его:

1. Перейдите в терминал, где запущен `jupyter notebook`.
2. Нажмите **Ctrl+C**.
3. При запросе подтверждения (Shutdown this Jupyter server?) введите `y` и Enter.

После остановки все открытые вкладки в браузере перестанут работать — сервер больше не отвечает. Данные в `.ipynb` сохранены на диске; при следующем запуске всё откроется заново.

## Частые ошибки

### Ошибка 1 — Полагаться только на закрытие браузера

Закрытие вкладки или браузера **не останавливает** сервер. Он продолжает работать в фоне, занимает порт и потребляет ресурсы. Останавливать нужно через Ctrl+C в терминале.

### Ошибка 2 — Порт уже занят

Если при запуске видите `OSError: [Errno 98] Address already in use`, порт 8888 занят другим процессом (часто — предыдущим экземпляром Jupyter). Используйте `--port 8889` или найдите и завершите процесс: `lsof -i :8888`.

### Ошибка 3 — Jupyter запущен в «чужом» venv

Если при установке вы забыли активировать venv, `jupyter notebook` мог запуститься из глобального Python или другого окружения. Ядро ноутбука будет использовать пакеты того окружения. Проверяйте: `which jupyter` — путь должен указывать внутрь вашего venv.
