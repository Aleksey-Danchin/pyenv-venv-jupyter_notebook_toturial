# Что такое Jupyter Notebook

> **Модуль 6 · Урок 1** | Время: ~10 мин

## Проблема: код и документация в одном месте

В модулях 0–5 вы научились управлять версиями Python (pyenv), пакетами (pip) и изолированными окружениями (venv). Теперь нужно удобная среда для **интерактивной разработки** — когда вы выполняете код по частям, смотрите результат, добавляете пояснения и снова запускаете.

Обычный `.py`-скрипт хорош для «запустил и забыл». Но для анализа данных, экспериментов, прототипирования и обучения хочется:

- Выполнять код **по ячейкам**, а не весь файл целиком.
- Смешивать **код и документацию** — пояснения, формулы, графики рядом с исполняемым кодом.
- Сохранять **воспроизводимый сценарий** — коллега открывает один файл и повторяет шаги.

## Что такое Jupyter Notebook

**Jupyter Notebook**[^глоссарий]([Глоссарий](../../references/glossary.md)) — это интерактивная среда для создания **ноутбуков** (notebooks). Ноутбук — это документ с чередующимися блоками кода и текста (Markdown), которые можно выполнять по отдельности.

С технической стороны Jupyter — это **два компонента**:

1. **Notebook-сервер** — процесс, который запускается в терминале и отдаёт веб-интерфейс.
2. **Браузерный интерфейс** — вы работаете с ноутбуками в браузере: создаёте ячейки, выполняете код, видите вывод.

Файл ноутбука имеет расширение `.ipynb` (IPython Notebook) — это JSON с ячейками, метаданными и результатами выполнения.

## Откуда название Jupyter

Проект вырос из **IPython** (интерактивный Python). Название *Jupyter* — акроним от **Ju**lia, **Pyt**hon, **R** (три языка, которые изначально поддерживались). Сейчас Jupyter поддерживает десятки языков через механизм **ядер** (kernels); ядро Python — самое распространённое. В модуле 7 вы узнаете, как регистрировать разные окружения как ядра.

## Чем ноутбук отличается от скрипта

| Критерий | .py скрипт | .ipynb ноутбук |
|----------|------------|----------------|
| Выполнение | Один запуск целиком | По ячейкам, в произвольном порядке |
| Документация | Комментарии `#` | Ячейки Markdown: заголовки, формулы, списки |
| Результат | print или логи | Вывод под каждой ячейкой (таблицы, графики) |
| Формат | Текст | JSON (код, вывод, метаданные) |

Ноутбук не заменяет скрипты — он для интерактивной работы, экспериментов и отчётов. Продакшен-код чаще держат в `.py`, а ноутбуки используют для анализа, прототипов и обучения.

## Связь с venv и pyenv

Jupyter устанавливается **внутри виртуального окружения** (venv). Ядро по умолчанию использует Python этого же окружения — то есть пакеты, установленные через `pip install` в venv, доступны в ячейках. Связка pyenv → venv → Jupyter будет подробно разобрана в модуле 7 (ядра). Сейчас важно: **сначала venv, потом `pip install jupyter notebook`**.

## Частые ошибки

### Ошибка 1 — Путать ноутбук с обычным скриптом

Ноутбук — это не «Python-файл с картинками». Ячейки выполняются по одной; порядок выполнения может отличаться от визуального порядка ячеек. Переменные сохраняются в памяти kernel'а между запусками. Если вы изменили код в ячейке выше и не перезапустили её — результаты могут быть неожиданными. Решение: Kernel → Restart & Run All, когда нужно «с чистого листа».

### Ошибка 2 — Не понимать, что Jupyter — это сервер

Jupyter не открывает `.ipynb` как обычный редактор. Вы запускаете **сервер** командой `jupyter notebook`, и **браузер** подключается к нему. Без работающего сервера интерфейс недоступен. Остановка сервера — Ctrl+C в том терминале, где он запущен.

### Ошибка 3 — Устанавливать Jupyter глобально

Jupyter лучше ставить в venv проекта. Глобальная установка смешивает пакеты с системным Python; при нескольких проектах будет путаница с пакетами и версиями. Курс рекомендует: venv → `pip install jupyter notebook` → работать в этом окружении.
