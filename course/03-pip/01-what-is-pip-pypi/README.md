# Что такое pip и PyPI

> **Модуль 3 · Урок 1** | Время: ~15 мин

## pip — менеджер пакетов Python

**pip** — это стандартный менеджер пакетов Python (см. [глоссарий](../../references/glossary.md)). Он устанавливает, удаляет и обновляет Python-библиотеки. pip входит в состав современного Python (начиная с 3.4) и используется повсеместно.

В модуле 0 вы уже познакомились с pip: он устанавливает пакеты в директорию **site-packages**[^глоссарий] — туда, где Python ищет импортируемые модули.

[^глоссарий]: [Глоссарий](../../references/glossary.md)

## pip связан с конкретным Python

Важно понимать: pip — это **не отдельная утилита**, а инструмент, привязанный к конкретному интерпретатору Python.

Проверьте, к какому Python привязан pip:

```bash
pip3 --version
```

```
pip 24.0 from /home/user/.pyenv/versions/3.12.0/lib/python3.12/site-packages/pip (python 3.12)
```

Или явно через модуль Python:

```bash
python3 -m pip --version
```

Рекомендуемый подход — запускать pip как модуль (`python3 -m pip`). Так вы гарантированно используете pip того интерпретатора, который вызываете.

Если вы используете pyenv (модули 1–2), команда `python3` уже указывает на выбранную версию. Соответственно, `python3 -m pip` устанавливает пакеты **именно в окружение этой версии**.

## Что такое PyPI

**PyPI** (Python Package Index, см. [глоссарий](../../references/glossary.md)) — репозиторий Python-пакетов. Это центральный каталог, откуда pip по умолчанию скачивает пакеты. Сайт: [pypi.org](https://pypi.org).

Любой разработчик может опубликовать пакет на PyPI. Когда вы выполняете `pip install requests`, pip обращается к PyPI, находит пакет `requests` и устанавливает его вместе с зависимостями.

## pip vs системный пакетный менеджер

| Аспект | pip | apt (Ubuntu) |
|--------|-----|--------------|
| Область | Python-пакеты (библиотеки) | Системные пакеты, в т.ч. `python3-*` |
| Источник | PyPI | Репозитории Ubuntu |
| Права | Обычно без sudo (в venv или пользовательский site-packages) | Требует sudo для системной установки |
| Управление | `pip install`, `pip uninstall` | `apt install`, `apt remove` |

Подробнее о различиях pip и apt — в уроке 07. Здесь важно: **pip и apt — разные инструменты**. Не устанавливайте Python-библиотеки через `apt`, если нет явной причины (например, системные скрипты, зависящие от `python3-requests`).

## Частые ошибки

### Ошибка 1 — Путать pip с apt

pip устанавливает **Python-пакеты** (библиотеки для импорта в коде). apt устанавливает **системные пакеты**, включая сам Python и служебные модули. Команда `apt install python3-requests` ставит системную копию `requests` — её не обновляет pip, и она может конфликтовать с venv.

### Ошибка 2 — Не понимать, что pip привязан к интерпретатору

Команда `pip install` без указания интерпретатора может установить пакет «не туда» — в окружение другого Python. Всегда проверяйте: `python3 -m pip --version` покажет, куда пойдёт установка.

### Ошибка 3 — Ожидать, что pip установит сам Python

pip устанавливает **пакеты**, а не интерпретатор. Для управления версиями Python используется pyenv (модули 1–2).
