## Вопрос 1

Какой интерпретатор Python используется при выполнении команды `pip install requests`?

- A) Всегда системный Python
- B) Тот, на который указывает команда `pip` в PATH (может различаться)
- C) Python, установленный через pyenv по умолчанию
- D) Любой Python в системе — pip сам выбирает

<details><summary>Ответ</summary>

**B)** — команда `pip` запускает тот pip, который найден первым в `PATH`. Он привязан к конкретному интерпретатору Python. Рекомендуется использовать `python -m pip` для явного указания интерпретатора.

</details>

## Вопрос 2

Что такое PyPI?

- A) Система типов в Python
- B) Репозиторий Python-пакетов, из которого pip по умолчанию загружает библиотеки
- C) Менеджер версий Python
- D) Инструмент для создания виртуальных окружений

<details><summary>Ответ</summary>

**B)** — PyPI (Python Package Index) — центральный репозиторий Python-пакетов. pip по умолчанию ищет пакеты именно там.

</details>

## Вопрос 3

В чём разница между `pip list` и `pip freeze`?

- A) Никакой — это синонимы
- B) `pip list` показывает все пакеты, `pip freeze` — только установленные вручную
- C) `pip freeze` выводит в формате `package==version`, подходящем для `requirements.txt`; `pip list` — табличный вывод
- D) `pip freeze` быстрее выполняется

<details><summary>Ответ</summary>

**C)** — `pip freeze` выводит список в формате `package==version`, который можно сохранить в `requirements.txt` и использовать для воспроизведения окружения. `pip list` показывает пакеты в табличном виде с версиями.

</details>

---

## Вопрос 4

Как установить пакеты из файла `requirements.txt`?

- A) `pip install requirements.txt`
- B) `pip install -r requirements.txt`
- C) `pip freeze -r requirements.txt`
- D) `pip load requirements.txt`

<details><summary>Ответ</summary>

**B)** — флаг `-r` (или `--requirement`) указывает pip установить все пакеты из указанного файла.

</details>

---

## Вопрос 5

Почему лучше указывать версию пакета при `pip install` (например, `pip install requests==2.31.0`)?

- A) Без версии pip не устанавливает пакет
- B) Это ускоряет установку
- C) Для воспроизводимости окружения — без фиксации версии разные установки могут дать разные результаты
- D) pip требует обязательного указания версии

<details><summary>Ответ</summary>

**C)** — без указания версии pip устанавливает последнюю доступную. Со временем «последняя» меняется, и окружение на другой машине или через полгода может оказаться иным. Фиксация версий обеспечивает воспроизводимость.

</details>

## Вопрос 6

Куда pip сохраняет скачанные пакеты для повторного использования?

- A) В домашнюю директорию пользователя
- B) В кеш pip (по умолчанию `~/.cache/pip/`)
- C) Только в site-packages, кеша нет
- D) В `/tmp/`

<details><summary>Ответ</summary>

**B)** — pip кеширует скачанные wheel-файлы и исходники в директории кеша (по умолчанию `~/.cache/pip/`). Это ускоряет повторные установки.

</details>

## Вопрос 7

Что произойдёт, если выполнить `pip install` без виртуального окружения и без явного указания пути?

- A) pip откажется устанавливать
- B) Пакеты будут установлены в site-packages того Python, к которому привязан pip (системный или pyenv)
- C) pip создаст виртуальное окружение автоматически
- D) Пакеты установятся в текущую директорию

<details><summary>Ответ</summary>

**B)** — pip устанавливает пакеты в site-packages того интерпретатора Python, с которым он связан. Это может быть системный Python или версия из pyenv. Глобальная установка рискованна — лучше использовать venv (модуль 4).

</details>

## Вопрос 8

Какая команда покажет метаданные установленного пакета (версия, расположение, зависимости)?

- A) `pip list <package>`
- B) `pip show <package>`
- C) `pip info <package>`
- D) `pip describe <package>`

<details><summary>Ответ</summary>

**B)** — `pip show <package>` выводит имя, версию, summary, зависимости и путь к установленным файлам пакета.

</details>

## Вопрос 9

Вы используете pyenv с `pyenv global 3.12.0`. Куда pip установит пакет при выполнении `pip install numpy`?

- A) В `/usr/lib/python3.12/site-packages/`
- B) В `~/.pyenv/versions/3.12.0/lib/python3.12/site-packages/`
- C) В `/usr/local/lib/python3.12/site-packages/`
- D) pip спросит пользователя

<details><summary>Ответ</summary>

**B)** — pip привязан к активному Python. При `pyenv global 3.12.0` команда `python` и `pip` указывают на Python из `~/.pyenv/versions/3.12.0/`, поэтому пакеты устанавливаются в его site-packages.

</details>

## Вопрос 10

Чем pip отличается от apt при установке Python-пакетов?

- A) pip и apt делают одно и то же
- B) apt устанавливает системные зависимости и python3-* пакеты; pip устанавливает пакеты из PyPI в окружение Python
- C) pip быстрее apt
- D) apt умеет обновлять pip-пакеты

<details><summary>Ответ</summary>

**B)** — apt управляет системными пакетами (включая `python3-*` для системных инструментов). pip устанавливает Python-библиотеки из PyPI. Смешивать их для одних и тех же пакетов не рекомендуется — могут возникнуть конфликты.

</details>
