# Лабораторная-диагностика: Конфликт pyenv local vs venv от другой версии

> **Модуль 11 · Диагностика 7** | Время: ~25 мин

## Сценарий

Коллега прислал проект с файлом `.python-version` (указана Python 3.11.7). Вы скопировали его, установили зависимости и создали venv. Но при работе возникают странности: в одних местах используется Python 3.11, в других — 3.12. Jupyter-ядро показывает не ту версию, что ожидается.

## Воспроизведение проблемы

Запустите скрипт, создающий «сломанное» состояние:

```bash
bash break.sh
```

Скрипт создаст проект `~/m11-debug-conflict` с `.python-version`, venv и зарегистрированным ядром, но версия в `.python-version` и версия, на которой построен venv, не совпадают.

## Симптомы

- `pyenv version` в директории проекта показывает 3.11.7 (из `.python-version`).
- При активации venv команда `python --version` показывает 3.12.x.
- Ядро Jupyter в ноутбуке использует Python 3.12.
- Возможны несовместимости или путаница при установке пакетов.

## Задание

Найдите причину рассинхрона и приведите окружение к согласованному состоянию: `.python-version`, venv и ядро должны соответствовать одной версии Python (3.11.7).

## Подсказка 1

<details><summary>Показать подсказку</summary>

Проверьте: `cat .python-version` и `./venv/bin/python --version`. Сравните версии. Если они отличаются — venv создан не на той версии Python, которая указана в `.python-version`.

</details>

## Подсказка 2

<details><summary>Показать подсказку</summary>

Виртуальное окружение «запоминает», с каким интерпретатором было создано. Если venv создан на Python 3.12, он всегда будет использовать 3.12, даже при наличии `.python-version` 3.11. Решение: удалить venv, убедиться, что `pyenv local 3.11.7` активен, затем пересоздать venv и переустановить зависимости. После этого перерегистрировать ядро.

</details>

## Самопроверка

После исправления в `~/m11-debug-conflict`:

```bash
cd ~/m11-debug-conflict
pyenv version
# Ожидается: 3.11.7 (set by ...)

source venv/bin/activate
python --version
# Ожидается: Python 3.11.7

deactivate
bash check.sh
```

**Ожидаемый результат:** все проверки пройдены, `python --version` в venv показывает 3.11.7.
