# Урок и тренажёр: Удаление проекта

> **Модуль 11 · Урок + Тренажёр 5** | Время: ~25 мин

## Цель

Научиться корректно удалять Python-проект: деактивировать venv, удалить окружение и ядро Jupyter, очистить локальную версию pyenv. Понимать, почему важен порядок действий.

## Теория: почему порядок важен

При удалении проекта с настроенным окружением нужно выполнить шаги в определённой последовательности:

1. **Деактивировать venv** — иначе активное окружение будет указывать на удалённую директорию, команды `python` и `pip` могут вести себя непредсказуемо.
2. **Удалить ядро Jupyter** — иначе в списке Kernel → Change kernel останется «битое» ядро, ссылающееся на несуществующий Python.
3. **Удалить venv** — физически удалить директорию окружения.
4. **Убрать .python-version** (опционально) — чтобы pyenv не «привязывал» текущую директорию к удалённой версии при последующем использовании папки.

Если удалить venv до деактивации, shell останется в «подвешенном» состоянии: `VIRTUAL_ENV` указывает на несуществующий путь.

---

## Подготовка

Создайте временный проект для практики удаления. Выполните следующие команды (или используйте проект из тренажёра 01):

```bash
mkdir -p ~/m11-removal-demo && cd ~/m11-removal-demo
pyenv local 3.11.7   # или другую установленную версию
python -m venv venv
source venv/bin/activate
pip install jupyter ipykernel
python -m ipykernel install --user --name m11-removal-demo --display-name "Python (m11-removal-demo)"
pip freeze > requirements.txt
deactivate
```

Теперь у вас есть проект с venv и зарегистрированным ядром. Задача — корректно его удалить.

---

## Шаг 1 — Деактивировать venv (если активирован)

Если вы находитесь внутри активированного venv, сначала выйдите:

```bash
deactivate
```

**Ожидаемый результат:** префикс `(venv)` исчезает из приглашения. Команда `python` снова указывает на версию из pyenv.

> **Что произошло:** переменная `VIRTUAL_ENV` сброшена; shell больше не привязан к venv.

---

## Шаг 2 — Удалить ядро Jupyter

Удалите зарегистрированное ядро, чтобы оно не осталось в списке «битых»:

```bash
jupyter kernelspec remove m11-removal-demo
```

**Ожидаемый результат:**

```
Removed kernelspec m11-removal-demo
```

> **Что произошло:** Jupyter больше не знает о ядре; в Kernel → Change kernel оно исчезнет.

---

## Шаг 3 — Удалить директорию venv

Перейдите в корень проекта и удалите окружение:

```bash
cd ~/m11-removal-demo
rm -rf venv/
```

**Ожидаемый результат:** директория `venv/` исчезает.

> **Что произошло:** виртуальное окружение удалено. Все установленные в нём пакеты больше недоступны.

---

## Шаг 4 — Убрать .python-version (опционально)

Если вы больше не планируете использовать эту папку как Python-проект, удалите привязку pyenv:

```bash
cd ~/m11-removal-demo
pyenv local --unset
```

**Ожидаемый результат:** файл `.python-version` удалён. В этой директории pyenv будет использовать глобальную версию.

> **Что произошло:** папка больше не «привязана» к конкретной версии Python. Саму папку с кодом можно оставить или удалить по необходимости.

---

## Итог

Вы выполнили полный цикл удаления: деактивация → удаление ядра → удаление venv → сброс pyenv local. Проект «разобран» корректно; не осталось зависших ссылок и битых ядер.

## Проверка

Запустите скрипт проверки:

```bash
bash check.sh
```

**Ожидаемый результат:** все пункты помечены как PASS (ядро удалено, venv удалён).
