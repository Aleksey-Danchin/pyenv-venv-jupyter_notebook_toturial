# .gitignore для Python-проектов

> **Модуль 10 · Урок 2** | Время: ~10 мин

## Зачем нужен .gitignore

**.gitignore** — файл в корне репозитория, который указывает git, какие файлы и папки не отслеживать[^глоссарий](../../references/glossary.md). В Python-проектах есть артефакты, которые создаются автоматически и не должны попадать в репозиторий: виртуальные окружения, кеш, чекпоинты Jupyter, секреты.

Без `.gitignore` вы рискуете закоммитить сотни мегабайт venv, временные файлы и чувствительные данные.

## Что исключать в Python-проекте

### Виртуальное окружение (venv)

```
venv/
.venv/
env/
```

Директория venv содержит копию интерпретатора и все пакеты. Она воспроизводится по `requirements.txt` и `.python-version`. Коммитить venv — пустая трата места и дублирование.

### Кеш Python

```
__pycache__/
*.py[cod]
*$py.class
*.so
.Python
```

`__pycache__/` — скомпилированные байт-код файлы (`.pyc`). Они генерируются автоматически при импорте модулей. На другой машине Python создаст их заново.

### Jupyter

```
.ipynb_checkpoints/
*.ipynb_checkpoints
```

Jupyter сохраняет чекпоинты — копии ноутбуков при автосохранении. Они нужны только для восстановления при сбое; в репозиторий их не включают.

### Секреты и конфигурация

```
.env
.env.local
*.pem
secrets.json
```

Файлы с паролями, API-ключами и токенами не должны попадать в git. Используйте `.env` для локальных настроек и добавьте её в `.gitignore`.

### Сборка и артефакты

```
dist/
build/
*.egg-info/
*.egg
```

Артефакты сборки пакетов (wheel, sdist) и промежуточные директории обычно пересобираются. Не коммитить.

### IDE и ОС

```
.idea/
.vscode/
.DS_Store
Thumbs.db
```

Настройки IDE и служебные файлы ОС — личные, не для общего репозитория.

## Типовой .gitignore для Python

```
# Виртуальные окружения
venv/
.venv/
env/

# Кеш Python
__pycache__/
*.py[cod]
*$py.class
*.so

# Jupyter
.ipynb_checkpoints/

# Секреты
.env
.env.local

# Сборка
dist/
build/
*.egg-info/
*.egg

# IDE и ОС
.idea/
.vscode/
.DS_Store
```

Создайте файл `.gitignore` в корне проекта **до** первого коммита. Иначе уже отслеживаемые файлы продолжат попадать в историю, даже после добавления их в `.gitignore`.

## Расположение .gitignore

Файл `.gitignore` лежит в **корне репозитория** (рядом с `README.md`, `requirements.txt`). Git применяет правила из этого файла рекурсивно ко всем поддиректориям.

## Частые ошибки

### Ошибка 1 — Коммитить venv

Очень частая ошибка новичков. venv может занимать сотни мегабайт. Коллега сможет воспроизвести окружение по `pip install -r requirements.txt` в своём venv. Никогда не коммитьте `venv/`, `.venv/`, `env/`.

### Ошибка 2 — Забыть .ipynb_checkpoints

При работе с Jupyter в проекте папки `.ipynb_checkpoints/` появляются рядом с ноутбуками. Без записи в `.gitignore` они случайно попадут в коммит. Добавьте `.ipynb_checkpoints/` в `.gitignore`.

### Ошибка 3 — Создать .gitignore после первого коммита с venv

Если вы уже закоммитили `venv/`, добавление `venv/` в `.gitignore` не удалит его из истории. Новые изменения в venv перестанут отслеживаться, но старые коммиты останутся. Лучше создать `.gitignore` до `git init` или до первого `git add`, и никогда не добавлять venv в индекс.

### Ошибка 4 — Закоммитить .env с паролями

Файл `.env` часто содержит `DATABASE_URL`, `API_KEY` и подобное. Один неосторожный коммит — и секреты в публичном репозитории. Всегда добавляйте `.env` в `.gitignore` и храните пример конфигурации в отдельном файле (например, `.env.example`) без реальных значений.
