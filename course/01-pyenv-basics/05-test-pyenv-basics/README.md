# Тест: pyenv — установка и основы

> **Модуль 1 · Тест** | Охватывает уроки 01–04

---

## Вопрос 1

Какую задачу решает pyenv?

- A) Создаёт виртуальные окружения для изоляции пакетов
- B) Управляет версиями интерпретатора Python
- C) Устанавливает Python-пакеты из PyPI
- D) Заменяет системный Python на более новый

<details><summary>Ответ</summary>

**B)** — pyenv управляет версиями интерпретатора Python: позволяет устанавливать, переключать и удалять версии. Виртуальные окружения — задача venv, пакеты — задача pip.

</details>

---

## Вопрос 2

Куда pyenv устанавливает версии Python?

- A) `/usr/bin/`
- B) `/usr/local/bin/`
- C) `~/.pyenv/versions/`
- D) `/opt/python/`

<details><summary>Ответ</summary>

**C)** — все версии хранятся в `~/.pyenv/versions/`, в домашней директории пользователя. Это не требует прав суперпользователя и не затрагивает системный Python.

</details>

---

## Вопрос 3

Что такое shim в контексте pyenv?

- A) Отдельный интерпретатор Python
- B) Конфигурационный файл pyenv
- C) Скрипт-обёртка, который перехватывает вызов команды и перенаправляет на нужную версию
- D) Симлинк на системный Python

<details><summary>Ответ</summary>

**C)** — shim — это легковесный скрипт в `~/.pyenv/shims/`, который перехватывает вызов (например, `python`) и перенаправляет его на версию Python, выбранную pyenv.

</details>

---

## Вопрос 4

Почему pyenv нужно добавлять в `PATH` раньше `/usr/bin`?

- A) Иначе pyenv не сможет скомпилировать Python
- B) Иначе shims не перехватят вызовы `python` — shell найдёт системный Python первым
- C) Это требование безопасности Linux
- D) Иначе `pyenv install` не будет работать

<details><summary>Ответ</summary>

**B)** — shell ищет команды по `PATH` слева направо. Если `~/.pyenv/shims/` стоит раньше `/usr/bin/`, shim перехватит вызов `python`. Иначе запустится системный Python, минуя pyenv.

</details>

---

## Вопрос 5

Для чего нужны зависимости сборки (build dependencies) при работе с pyenv?

- A) Для запуска Python-скриптов
- B) Для скачивания исходников Python
- C) Для компиляции Python из исходников
- D) Для обновления pyenv

<details><summary>Ответ</summary>

**C)** — pyenv компилирует Python из исходников. Для этого нужны компилятор C (`build-essential`) и заголовочные файлы библиотек (`libssl-dev`, `zlib1g-dev` и др.).

</details>

## Вопрос 6

Что произойдёт, если выполнить `pyenv install 3.12.0`, когда зависимости сборки не установлены?

- A) pyenv установит предкомпилированный бинарник
- B) Компиляция завершится с ошибкой
- C) pyenv автоматически установит зависимости
- D) Установится Python без стандартной библиотеки

<details><summary>Ответ</summary>

**B)** — компиляция завершится с ошибкой. pyenv не устанавливает зависимости автоматически — вывод ошибки укажет, какого пакета не хватает. Зависимости нужно установить вручную через `apt`.

</details>

## Вопрос 7

Чем отличается `pyenv version` от `pyenv versions`?

- A) Ничем — это синонимы
- B) `pyenv version` показывает текущую активную версию, `pyenv versions` — все установленные
- C) `pyenv version` показывает версию pyenv, `pyenv versions` — версии Python
- D) `pyenv versions` работает только с правами суперпользователя

<details><summary>Ответ</summary>

**B)** — `pyenv version` (без `s`) выводит только текущую активную версию. `pyenv versions` (с `s`) выводит все установленные версии, отмечая активную звёздочкой.

</details>

---

## Вопрос 8

Что означает `system` в выводе `pyenv versions`?

- A) Версия Python, установленная через pyenv по умолчанию
- B) Системный Python, установленный пакетным менеджером ОС
- C) Директория, где pyenv хранит свои файлы
- D) Специальная версия для системных скриптов pyenv

<details><summary>Ответ</summary>

**B)** — `system` в выводе pyenv обозначает системный Python (`/usr/bin/python3`), установленный пакетным менеджером ОС. pyenv всегда знает о нём.

</details>

---

## Вопрос 9

Вы выполнили `pyenv install --list`, но не нашли Python 3.14.0, хотя он уже выпущен. В чём причина?

- A) Python 3.14 несовместим с pyenv
- B) Нужно обновить pyenv — список версий зашит в его коде
- C) Нужно переустановить pyenv с нуля
- D) Нужно обновить `apt` репозитории

<details><summary>Ответ</summary>

**B)** — список доступных версий хранится в коде pyenv. Обновите его командой `cd ~/.pyenv && git pull`, и новые версии появятся в списке.

</details>

---

## Вопрос 10

Какая из этих команд покажет, что системный Python по-прежнему находится в `/usr/bin/`?

- A) `pyenv versions`
- B) `pyenv version`
- C) `which python3` (без активного pyenv)
- D) Все перечисленные

<details><summary>Ответ</summary>

**C)** — `which python3` (в чистом shell без pyenv) покажет путь `/usr/bin/python3`. Команды `pyenv versions` и `pyenv version` показывают информацию об управляемых pyenv версиях, а не о расположении системного Python.

</details>
