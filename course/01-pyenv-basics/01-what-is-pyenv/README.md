# Что такое pyenv и зачем он нужен

> **Модуль 1 · Урок 1** | Время: ~5 мин

## Проблема: одна версия Python на всё

В модуле 0 вы узнали, что в Ubuntu предустановлен системный Python. Он привязан к конкретной версии (например, 3.12), и менять его опасно — от него зависят системные утилиты.

Но что, если вам нужен Python 3.10 для одного проекта и 3.13 для другого? Или вы хотите попробовать свежий релиз, не трогая рабочую среду?

Стандартные средства ОС здесь не помогут:

```bash
sudo apt install python3.10 python3.13
```

Даже если в репозиториях есть нужные версии (а их часто нет), вы получите конфликты и неуправляемый зоопарк бинарников в `/usr/bin/`.

## Что такое pyenv

**pyenv** — это менеджер версий Python[^глоссарий]([Глоссарий](../../references/glossary.md)). Он позволяет:

- Устанавливать любую версию CPython (и не только) — от древней 2.7 до последнего релиза.
- Держать несколько версий одновременно, не конфликтуя с системным Python.
- Переключаться между версиями одной командой.

pyenv не требует прав суперпользователя для установки версий Python. Все версии хранятся в домашней директории пользователя (`~/.pyenv/versions/`), полностью изолированно от системного Python.

## Как pyenv работает: shims

В модуле 0 вы познакомились с понятием **shim**. Именно на этом механизме построен pyenv.

При установке pyenv добавляет в начало вашего `PATH` директорию `~/.pyenv/shims/`. В ней лежат легковесные скрипты-обёртки (shims) для команд `python`, `pip` и других. Когда вы вводите `python`, shell находит shim первым — раньше, чем системный `/usr/bin/python3`.

Shim не запускает Python напрямую. Вместо этого он:

1. Определяет, какая версия Python сейчас активна (через переменные окружения, файл `.python-version` или глобальную настройку).
2. Перенаправляет вызов на соответствующий бинарник в `~/.pyenv/versions/`.

```
Вызов: python
    ↓
~/.pyenv/shims/python  (shim — перехватывает вызов)
    ↓
pyenv определяет нужную версию
    ↓
~/.pyenv/versions/3.12.0/bin/python  (реальный бинарник)
```

Благодаря этому вы переключаете версию Python одной командой, а все скрипты и инструменты продолжают вызывать просто `python` — shim сам разберётся.

## Что pyenv НЕ делает

Важно понимать границы инструмента:

- pyenv **не управляет пакетами** — для этого есть pip.
- pyenv **не создаёт виртуальные окружения** — для этого есть venv (модуль 4).
- pyenv **не трогает системный Python** — он работает параллельно.

pyenv решает ровно одну задачу: управление версиями интерпретатора Python.

## Сравнение с альтернативами

### pyenv vs `apt install python3.x`


| Критерий            | `apt install`                             | pyenv                                        |
| ------------------- | ----------------------------------------- | -------------------------------------------- |
| Доступные версии    | Только то, что есть в репозиториях Ubuntu | Любая версия CPython (и другие реализации)   |
| Права               | Требует `sudo`                            | Работает от обычного пользователя            |
| Изоляция от системы | Нет — ставится в `/usr/bin/`              | Полная — всё в `~/.pyenv/`                   |
| Переключение версий | Ручное, через полный путь                 | Одна команда (`pyenv global`, `pyenv local`) |
| Удаление версий     | `apt remove`, может затронуть зависимости | `pyenv uninstall` — чистое удаление          |


`apt install python3.x` подходит, когда вам нужна одна конкретная версия и вы готовы зависеть от того, что предлагает дистрибутив. Для разработки с несколькими проектами и версиями — pyenv значительно удобнее.

## Частые ошибки

### Ошибка 1 — Путаница pyenv и venv

pyenv управляет **версиями интерпретатора** (Python 3.10, 3.12, 3.13). venv создаёт **изолированные окружения с пакетами** для конкретного проекта. Это разные инструменты, которые дополняют друг друга. Вы будете использовать их вместе начиная с модуля 5.

### Ошибка 2 — Попытка установить pyenv через pip

pyenv — это **не Python-пакет**. Команда `pip install pyenv` установит совсем другой пакет, не имеющий отношения к менеджеру версий. pyenv устанавливается через клонирование Git-репозитория или специальный скрипт-установщик (об этом — в следующем юните).

### Ошибка 3 — Ожидание, что pyenv заменит системный Python

pyenv не удаляет и не подменяет системный Python. Системные утилиты продолжают использовать `/usr/bin/python3`. pyenv добавляет свой слой *поверх* — через shims в `PATH`.
