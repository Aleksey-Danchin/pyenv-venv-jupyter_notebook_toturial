# Конспект: Python-среда в Linux

> Модуль 0 — краткая справка для печати и повторения.

---

## Ключевые понятия

| Понятие | Определение |
|---------|-------------|
| Системный Python | Python, установленный пакетным менеджером ОС. Используется системными утилитами. |
| PATH | Переменная окружения: список директорий, где shell ищет команды (слева направо). |
| Симлинк | Файл-ссылка на другой файл. Цепочка: `python` → `python3` → `python3.12`. |
| site-packages | Директория, куда pip устанавливает пакеты. |
| Shim | Прокси-файл, перехватывающий вызов команды и направляющий его на нужную версию. |

---

## Команды-минимум

| Команда | Что делает | Пример |
|---------|-----------|--------|
| `which python3` | Какой бинарь запустится | `/usr/bin/python3` |
| `whereis python3` | Все известные расположения | бинарь, библиотеки, man |
| `type -a python3` | Все варианты команды по PATH | в порядке приоритета |
| `echo $PATH` | Текущий порядок поиска | директории через `:` |
| `ls -l /usr/bin/python3` | Симлинк ли это и куда | `-> python3.12` |
| `readlink -f /usr/bin/python3` | Конечный файл цепочки | `/usr/bin/python3.12` |
| `python3 --version` | Версия активного Python | `Python 3.12.x` |
| `python3 -m pip --version` | Какой pip и к какому Python | путь `from ...` |
| `python3 -m site` | Пути site-packages | системные и пользовательские |

---

## Важно запомнить

- `which` отвечает «что запустится сейчас», `whereis` — «где в системе встречается».
- PATH просматривается **слева направо** — первый найденный бинарь побеждает.
- `type -a` показывает все варианты команды в порядке приоритета.
- Симлинк — это ссылка, не копия. Цепочка может быть многоуровневой — используйте `readlink -f`.
- Системный Python **не ваш рабочий инструмент** — от него зависят утилиты ОС.
- Запускайте pip как `python3 -m pip` — так вы явно контролируете интерпретатор.
- Глобальная установка пакетов ведёт к конфликтам между проектами — для этого есть venv.
- Shim — маршрутизатор вызова, не интерпретатор. Корректный PATH критичен для его работы.

## Типичные ошибки (коротко)

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `python: command not found` | В Ubuntu может не быть симлинка `python` | Использовать `python3` |
| `which` и `whereis` дают разное | Это разные инструменты: запуск vs расположение | `which` — что запустится, `whereis` — где лежит |
| «Python сменился сам» | Изменился симлинк или порядок PATH | Проверить `readlink -f` и `echo $PATH` |
| pip ставит «не туда» | pip привязан к другому интерпретатору | Проверить `python3 -m pip --version` |
| Конфликт версий библиотек | Глобальная установка для разных проектов | Использовать venv (следующие модули) |
| pyenv не работает | Директория shims не в начале PATH | Проверить `echo $PATH` и настройку shell |

## Цепочка симлинков (типичная Ubuntu)

```
/usr/bin/python  →  /usr/bin/python3  →  /usr/bin/python3.12
   (симлинк)           (симлинк)           (реальный файл)
```

Проверка:

```bash
ls -l /usr/bin/python3        # показывает первый уровень
readlink -f /usr/bin/python3  # показывает конечную цель
```

## Чеклист диагностики

Если Python или pip ведут себя «не так» — пройдитесь по списку:

1. `which python3` — тот ли бинарь запускается?
2. `echo $PATH` — нет ли неожиданной директории раньше `/usr/bin`?
3. `ls -l $(which python3)` — не указывает ли симлинк на другую версию?
4. `readlink -f $(which python3)` — какой реальный файл в конце цепочки?
5. `python3 -m pip --version` — pip привязан к ожидаемому Python?
6. `python3 -m site` — пакеты ищутся в правильных директориях?

---

## Правила безопасности

1. **Не удалять** системный Python и его пакеты — от них зависят утилиты ОС.
2. **Не подменять** симлинки в `/usr/bin` вручную — используйте pyenv для управления версиями.
3. **Не ставить** рабочие зависимости глобально — используйте venv для изоляции.
