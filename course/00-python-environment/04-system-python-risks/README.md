# Почему нельзя трогать системный Python (зависимости ОС)

> **Модуль 0 · Урок 04** | Время: ~5 мин

## Содержание

Системный Python участвует в работе служебных сценариев и инструментов ОС.  
Если удалить или подменить системные компоненты Python, можно получить:

- ошибки в системных утилитах;
- проблемы с пакетным менеджером;
- некорректную работу служебных скриптов.

Проверка текущего пути:

```bash
which python3
ls -l /usr/bin/python3
```

Ключевая идея модуля: **системный Python не «ремонтируют» ручной заменой**.  
Для проектов создают отдельные версии (через pyenv) и изоляцию (через venv).

## Безопасный подход

1. Не удалять системные python-пакеты, если не понимаете последствия.
2. Не переписывать вручную `/usr/bin/python3`.
3. Работать с отдельной проектной средой, а не в системной установке.

## Частые ошибки

### Ошибка 1 — пытаться «обновить Python» через удаление системной версии

Это может повредить зависимости ОС и вызвать каскадные ошибки.

### Ошибка 2 — устанавливать рабочие зависимости проекта глобально

Глобальная установка может конфликтовать с системными пакетами и другими проектами.

### Ошибка 3 — считать, что один Python должен подходить для всего

На практике нужны разные версии Python для разных задач; это и решают pyenv и venv.
