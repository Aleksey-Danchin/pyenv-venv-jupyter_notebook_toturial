# Модуль 0. Python-среда в Linux

> **Время:** ~2–3 дня (при темпе 1–2 часа в день)

## Чему вы научитесь

- Определять, какой Python реально запускается в текущем shell.
- Объяснять, как `PATH` влияет на выбор исполняемых файлов.
- Читать цепочки симлинков `python -> python3 -> python3.x`.
- Оценивать риски изменения системного Python.
- Понимать, куда pip устанавливает пакеты при глобальной установке.
- Объяснять базовую идею `shims` перед изучением pyenv.

## Что будет рассмотрено

| Тема | Описание |
|------|----------|
| Системный Python | Где находятся бинарные файлы и как их найти командами shell. |
| PATH и разрешение команд | Почему одна и та же команда может запускать разные бинарники. |
| Симлинки | Как устроена переадресация `python` и как читать цепочку ссылок. |
| Системные зависимости | Почему нельзя «чинить» ОС через удаление системного Python. |
| pip в глобальном контексте | Где оказываются пакеты и откуда берутся конфликты. |
| Шаг к pyenv | Что такое `shim` и зачем нужен такой слой. |

## Инструменты и команды

| Команда / инструмент | Назначение |
|---------------------|-----------|
| `which`, `whereis` | Найти бинарный файл команды. |
| `echo $PATH` | Посмотреть порядок директорий поиска. |
| `ls -l`, `readlink -f` | Проверить симлинки и конечный путь. |
| `python3 -m site` | Показать директории Python, включая `site-packages`. |
| `pip3 --version` | Проверить связку pip и интерпретатора Python. |

## Итоги модуля

### Что вы изучили

- Как shell выбирает конкретный бинарник Python по `PATH`.
- Как устроены симлинки в цепочке вызова Python в Ubuntu.
- Почему системный Python связан с работой системных утилит.
- Как интерпретировать, куда именно ставит пакеты `pip`.
- Почему модель `shim` важна перед переходом к pyenv.

### Чеклист навыков

Отметьте то, что вы уверенно можете сделать:

- [ ] Показать путь к активному `python3` и объяснить, почему выбран именно он.
- [ ] Развернуть цепочку симлинков до конечного бинаря.
- [ ] Объяснить риск удаления или подмены системного Python.
- [ ] Определить, какой Python обслуживает текущий `pip`.
- [ ] Кратко объяснить, что делает `shim`.

### Ключевые команды

```bash
which python3
echo $PATH
ls -l /usr/bin/python3
readlink -f /usr/bin/python3
python3 -m site
python3 -m pip --version
```
