## Вопрос 1

Какая команда показывает, какой `python3` будет запущен прямо сейчас?

- A) `whereis python3`
- B) `which python3`
- C) `ls -l python3`
- D) `readlink python3`

Ответ

**B)** `which` показывает первый исполняемый файл, найденный по текущему `PATH`.



---

## Вопрос 2

Чем `whereis python3` отличается от `which python3`?

- A) Ничем, это полные аналоги
- B) `whereis` показывает только активный путь, `which` — все пути
- C) `which` показывает активный путь запуска, `whereis` — известные системе расположения
- D) `whereis` работает только для pip

Ответ

**C)** `which` отвечает на вопрос «что запустится», `whereis` показывает набор известных расположений.



---

## Вопрос 3

Что такое `PATH`?

- A) Системный каталог Python-пакетов
- B) Переменная окружения с путями поиска исполняемых файлов
- C) Тип симлинка
- D) Формат файла конфигурации pip

Ответ

**B)** `PATH` определяет порядок директорий, где shell ищет команды.



---

## Вопрос 4

Как shell выбирает команду при поиске по `PATH`?

- A) Случайно
- B) По дате изменения файла
- C) Справа налево
- D) Слева направо, первый найденный исполняемый файл

Ответ

**D)** Приоритет задаётся порядком директорий в `PATH`.



---

## Вопрос 5

Что делает `readlink -f /usr/bin/python3`?

- A) Удаляет симлинк
- B) Разворачивает цепочку симлинков до конечного файла
- C) Показывает версию Python
- D) Проверяет pip-конфигурацию

Ответ

**B)** Команда показывает конечную цель после всех промежуточных ссылок.



---

## Вопрос 6

Почему нельзя бездумно удалять/подменять системный Python?

- A) Потому что это просто неудобно
- B) Потому что pip перестанет запускаться из venv
- C) Потому что системные утилиты и зависимости ОС могут перестать работать
- D) Потому что это запрещено

Ответ

**C)** Системный Python часто участвует в работе служебных инструментов ОС.



---

## Вопрос 7

Где обычно оказываются пакеты при глобальной установке pip без venv?

- A) В `site-packages` системного или пользовательского Python
- B) Только в домашней папке проекта
- C) Только в `/tmp`
- D) Только в `/opt/pyenv`

Ответ

**A)** Путь зависит от контекста запуска и прав, но это всегда директории Python-пакетов.



---

## Вопрос 8

Зачем запускать pip как `python3 -m pip`?

- A) Это всегда быстрее
- B) Это гарантирует запуск pip через конкретный интерпретатор Python
- C) Иначе pip не видит интернет
- D) Это нужно только для Windows

Ответ

**B)** Так вы явно выбираете Python, который выполняет pip.



---

## Вопрос 9

Что такое shim в контексте pyenv?

- A) Новая версия Python
- B) Файл настройки Jupyter
- C) Прокси-исполняемый файл, перенаправляющий вызов команды
- D) Аналог `requirements.txt`

Ответ

**C)** Shim перехватывает вызов и маршрутизирует его к нужному бинарю.



---

## Вопрос 10

Что лучше всего объясняет связку тем этого модуля?

- A) Нужно только запомнить команды
- B) Если понимать `PATH`, симлинки и роль системного Python, проще диагностировать «не тот python/pip»
- C) Главное — сразу удалить системный Python и поставить pyenv
- D) Все проблемы решаются перезагрузкой shell

Ответ

**B)** Модуль формирует основу диагностики: как выбираются бинарники и почему это важно для стабильности системы.
