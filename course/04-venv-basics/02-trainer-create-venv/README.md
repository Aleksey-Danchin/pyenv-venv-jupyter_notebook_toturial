# Тренажёр: Создание виртуального окружения

> **Модуль 4 · Тренажёр 2** | Время: ~20 мин

## Цель

К концу тренажёра вы создадите виртуальное окружение в рабочей директории и убедитесь, что оно корректно создано.

## Подготовка

- Python 3.4+ (системный или через pyenv).
- Терминал bash или zsh.
- Создайте рабочую директорию для экспериментов (например, `~/venv-demo`).

---

## Шаг 1 — Выбор директории и интерпретатора

Перейдите в директорию, где будет проект (или эксперимент):

```bash
mkdir -p ~/venv-demo
cd ~/venv-demo
```

Убедитесь, что у вас доступен нужный Python:

```bash
python3 --version
```

**Ожидаемый результат:**

```
Python 3.12.0
```

(Версия может отличаться в зависимости от системы или pyenv.)

> **Что произошло:** вы создали рабочую директорию и проверили, что команда `python3` указывает на интерпретатор нужной версии. Именно этот интерпретатор будет базовым для создаваемого venv.

---

## Шаг 2 — Создание виртуального окружения

Создайте виртуальное окружение. Стандартная команда — `python -m venv` с указанием имени каталога:

```bash
python3 -m venv venv
```

Команда `python3 -m venv venv` запускает модуль `venv` из стандартной библиотеки. Аргумент `venv` — имя директории, в которой будет создано окружение (часто используют `venv` или `.venv`).

**Ожидаемый результат:**

Команда выполняется без вывода — это нормально. Через несколько секунд в текущей директории появится каталог `venv`.

> **Что произошло:** модуль venv создал изолированную структуру: `venv/bin/` (исполняемые файлы), `venv/lib/` (пакеты), `venv/pyvenv.cfg` (конфигурация). Внутри — симлинки или копии интерпретатора и pip.

---

## Шаг 3 — Проверка структуры

Убедитесь, что окружение создано:

```bash
ls -la venv/
```

**Ожидаемый результат:**

```
drwxr-xr-x  bin
drwxr-xr-x  lib
-rw-r--r--  pyvenv.cfg
```

Проверьте наличие ключевых файлов:

```bash
ls venv/bin/ | head -10
```

**Ожидаемый результат:**

```
activate
activate.csh
activate.fish
pip
pip3
python
python3
...
```

> **Что произошло:** вы убедились, что venv создал стандартную структуру. Скрипт `activate` используется для активации окружения (следующий урок). Файлы `python`, `pip` внутри `venv/bin/` указывают на интерпретатор и pip этого окружения.

---

## Шаг 4 — Проверка pyvenv.cfg

Файл `pyvenv.cfg` содержит ссылку на базовый Python:

```bash
cat venv/pyvenv.cfg
```

**Ожидаемый результат:**

```
home = /home/<user>/.pyenv/versions/3.12.0/bin
include-system-site-packages = false
version = 3.12.0
```

(Путь `home` зависит от того, откуда взят Python — pyenv или система.)

> **Что произошло:** `home` указывает на базовый интерпретатор, `include-system-site-packages = false` — пакеты из системного site-packages не видны в venv (чистая изоляция).

---

## Итог

Вы создали виртуальное окружение в директории `venv`. Окружение пока не активировано — активация и работа с ним будут в следующих уроках.

## Проверка

```bash
test -f venv/bin/activate && test -f venv/bin/python && echo "✅ venv создан"
```

**Ожидаемый результат:**

```
✅ venv создан
```

Либо запустите скрипт проверки:

```bash
bash check.sh
```
