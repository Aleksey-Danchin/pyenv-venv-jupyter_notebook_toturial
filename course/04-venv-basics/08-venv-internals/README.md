# Где физически хранится окружение, что внутри папки venv

> **Модуль 4 · Урок 8** | Время: ~10 мин

## Структура каталога venv

После `python -m venv venv` создаётся директория с типичной структурой:

```
venv/
├── bin/
│   ├── activate          # скрипт активации (bash)
│   ├── activate.csh      # для csh
│   ├── activate.fish     # для fish
│   ├── python            # симлинк или копия интерпретатора
│   ├── python3           # симлинк
│   ├── python3.12        # симлинк на бинарник базового Python
│   ├── pip               # wrapper для pip
│   └── pip3
├── lib/
│   └── python3.12/
│       └── site-packages/  # установленные пакеты
└── pyvenv.cfg            # конфигурация venv
```

## pyvenv.cfg

Файл `venv/pyvenv.cfg` определяет связь с **базовым** Python:

```
home = /home/user/.pyenv/versions/3.12.0/bin
include-system-site-packages = false
version = 3.12.0
```

- **home** — путь к базовому интерпретатору, от которого создан venv.
- **include-system-site-packages** — `false` по умолчанию (изоляция от системных пакетов).
- **version** — версия Python.

## bin/ — что внутри

- **activate** — shell-скрипт, который меняет `PATH` и переменные окружения.
- **python**, **python3** — обычно симлинки на бинарник базового Python в `home`. На некоторых системах — копии.
- **pip** — скрипт-обёртка, вызывающий `python -m pip`.

## lib/python3.x/site-packages/

Сюда попадают все пакеты при `pip install`. Структура та же, что у глобального site-packages, но физически отдельная.

## Связь с базовым Python

venv **не копирует** весь Python. Он использует базовый интерпретатор через симлинки. Копируются только необходимые части стандартной библиотеки (если требуется изоляция).

Если удалить базовый Python (например, через `pyenv uninstall 3.12.0`), venv **сломается** — симлинки перестанут указывать на существующий файл. Это рассматривается в модуле 5 (лабораторная-диагностика).

## Почему не коммитить venv в git

Директория venv:

- Занимает много места (десятки–сотни МБ).
- Содержит бинарники и пути, специфичные для вашей машины.
- Полностью воссоздаётся командой `python -m venv venv` + `pip install -r requirements.txt`.

Поэтому venv добавляют в `.gitignore`:

```
venv/
.venv/
```

Коллега клонирует репозиторий и создаёт своё окружение за минуту.

## Частые ошибки

### Ошибка 1 — Редактировать файлы внутри venv вручную

Файлы в `venv/` генерируются и обновляются Python и pip. Ручное изменение может сломать окружение. Используйте только `pip install`/`pip uninstall`.

### Ошибка 2 — Коммитить venv в репозиторий

venv — локальная артефактная директория. В git попадают только `requirements.txt` и `.python-version` (для pyenv).

### Ошибка 3 — Путать venv с pyenv

venv — это **каталог** с изолированным окружением (пакеты, интерпретатор). pyenv — **менеджер версий** Python, который живёт в `~/.pyenv/`. Они решают разные задачи и используются вместе.
