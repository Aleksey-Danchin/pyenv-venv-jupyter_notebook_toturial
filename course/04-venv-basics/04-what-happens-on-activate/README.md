# Что происходит при активации

> **Модуль 4 · Урок 4** | Время: ~10 мин

## Скрипт `activate` — что он делает

При выполнении `source venv/bin/activate` скрипт выполняет несколько действий:

1. **Меняет `PATH`** — добавляет `venv/bin/` в начало списка директорий.
2. **Устанавливает переменную `VIRTUAL_ENV`** — путь к корню окружения.
3. **Меняет приглашение (prompt)** — добавляет префикс `(venv)` для наглядности.
4. **Определяет функцию `deactivate`** — для отката изменений.

Благодаря этому команды `python`, `pip`, `easy_install` и другие исполняемые файлы из `venv/bin/` вызываются **раньше**, чем системные.

## Как переопределяются `python` и `pip`

До активации:

```bash
which python
# /home/user/.pyenv/shims/python  (или /usr/bin/python3)
```

После активации:

```bash
which python
# /home/user/project/venv/bin/python
```

Тот же принцип, что и в модуле 0: shell ищет исполняемые файлы по `PATH` **с начала списка**. Каталог venv теперь первый — он «перекрывает» системный Python.

## Переменная VIRTUAL_ENV

После активации в окружении появляется переменная `VIRTUAL_ENV`:

```bash
echo $VIRTUAL_ENV
# /home/user/project/venv
```

Скрипты и IDE могут проверять эту переменную, чтобы понять, какое окружение активно. Например, VS Code и PyCharm используют её для выбора интерпретатора.

## Deactivate — откат изменений

Команда `deactivate` (добавленная скриптом `activate`) восстанавливает прежний `PATH`, сбрасывает `VIRTUAL_ENV` и убирает префикс из prompt. После деактивации `which python` снова укажет на глобальный Python.

## Частые ошибки

### Ошибка 1 — Не понимать, что `python` после активации указывает внутрь venv

Некоторые считают, что активация лишь «помечает» окружение, а `python` остаётся тем же. На самом деле меняется `PATH`, и `python` начинает указывать на `venv/bin/python`. Все последующие вызовы (в том числе `pip install`) используют именно это окружение.

### Ошибка 2 — Полагаться на VIRTUAL_ENV при запуске скриптов извне

Если вы запускаете Python-скрипт через `cron`, systemd или другой процесс, который не наследует ваш shell, переменная `VIRTUAL_ENV` не установлена. Для таких случаев используйте полный путь к интерпретатору: `venv/bin/python script.py`.
