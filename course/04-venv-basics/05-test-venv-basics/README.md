# Тест: venv — создание, активация, деактивация

## Вопрос 1

Чем venv отличается от pyenv?

- A) venv и pyenv — это одно и то же
- B) pyenv управляет версиями интерпретатора Python; venv создаёт изолированные окружения с собственными пакетами
- C) venv управляет версиями Python, pyenv — пакетами
- D) pyenv встроен в Python, venv — внешний инструмент

<details><summary>Ответ</summary>

**B)** — pyenv решает задачу выбора версии Python (3.10, 3.12 и т.д.). venv решает задачу изоляции пакетов: каждое окружение имеет свой набор установленных библиотек, не затрагивая глобальный Python.

</details>

---

## Вопрос 2

Как создать виртуальное окружение в директории `venv` с помощью Python?

- A) `venv create venv`
- B) `python -m venv venv`
- C) `pip install venv && venv venv`
- D) `python venv venv`

<details><summary>Ответ</summary>

**B)** — модуль `venv` входит в стандартную библиотеку Python. Запускается как `python -m venv <путь>`, где путь — имя или директория для создания окружения.

</details>

---

## Вопрос 3

Как активировать виртуальное окружение в Linux (bash), если оно создано в директории `venv`?

- A) `venv\Scripts\activate`
- B) `source venv/bin/activate`
- C) `activate venv`
- D) `python venv activate`

<details><summary>Ответ</summary>

**B)** — в Linux и macOS скрипт активации находится в `venv/bin/activate` и выполняется через `source`, чтобы изменения применились к текущему shell.

</details>

---

## Вопрос 4

Что происходит с переменной PATH при активации venv?

- A) PATH не меняется
- B) Директория `venv/bin/` добавляется в начало PATH
- C) Системные пути удаляются из PATH
- D) PATH перезаписывается только путями venv

<details><summary>Ответ</summary>

**B)** — скрипт `activate` добавляет `venv/bin/` в начало PATH. Благодаря этому команды `python` и `pip` из venv вызываются раньше системных.

</details>

---

## Вопрос 5

Какая команда деактивирует виртуальное окружение?

- A) `exit`
- B) `deactivate`
- C) `venv deactivate`
- D) `source venv/bin/deactivate`

<details><summary>Ответ</summary>

**B)** — функция `deactivate` добавляется скриптом `activate`. Она восстанавливает прежний PATH и убирает переменную VIRTUAL_ENV.

</details>

## Вопрос 6

Почему при создании venv лучше использовать `python -m venv`, а не вызывать `venv` как отдельную команду?

- A) Команда `venv` не существует
- B) `python -m venv` гарантирует использование того интерпретатора Python, который вы вызвали; при `venv` может использоваться другой Python
- C) `venv` работает только в Windows
- D) `python -m venv` быстрее

<details><summary>Ответ</summary>

**B)** — модуль `venv` вызывается тем интерпретатором, который вы указали. Если вы используете pyenv и хотите создать venv на Python 3.11, команда `python -m venv venv` (при активном Python 3.11) создаст окружение именно на этой версии.

</details>

## Вопрос 7

Куда pip устанавливает пакеты при активном виртуальном окружении?

- A) В системный site-packages
- B) В site-packages внутри директории venv (venv/lib/python3.x/site-packages/)
- C) В текущую директорию
- D) В ~/.local/lib/python3.x/site-packages/

<details><summary>Ответ</summary>

**B)** — при активном venv команда `pip` указывает на `venv/bin/pip`, который связан с `venv/bin/python`. Пакеты устанавливаются в `venv/lib/python3.x/site-packages/` — изолированно от системы и других окружений.

</details>

## Вопрос 8

Что означает переменная окружения VIRTUAL_ENV после активации venv?

- A) Версия Python в venv
- B) Путь к корневой директории активного виртуального окружения
- C) Список установленных пакетов
- D) Флаг «окружение активно»

<details><summary>Ответ</summary>

**B)** — VIRTUAL_ENV содержит полный путь к корню venv (например, `/home/user/project/venv`). Скрипты и IDE используют её для определения активного окружения.

</details>

## Вопрос 9

Вы используете pyenv с Python 3.12. Как создать venv на базе именно этой версии?

- A) Сначала `pyenv global 3.12`, затем `venv venv`
- B) Убедиться, что `python` указывает на 3.12 (через pyenv global/local/shell), затем `python -m venv venv`
- C) `pip install venv-3.12`
- D) pyenv и venv несовместимы

<details><summary>Ответ</summary>

**B)** — venv создаётся на базе того интерпретатора, который вызывается командой `python`. Настройте pyenv так, чтобы `python` указывал на 3.12, затем выполните `python -m venv venv`. Окружение будет использовать именно эту версию.

</details>

## Вопрос 10

Можно ли использовать venv, созданный в директории проекта, в другом проекте?

- A) Да, достаточно указать полный путь при активации
- B) Технически можно, но не рекомендуется — venv привязан к версии Python и пакетам конкретного проекта
- C) Нет, venv работает только в той директории, где создан
- D) Да, если скопировать директорию venv

<details><summary>Ответ</summary>

**B)** — технически вы можете активировать любой venv, указав путь. Но каждый проект должен иметь собственное окружение с нужными зависимостями. Общий venv для нескольких проектов приведёт к конфликтам версий пакетов.

</details>
