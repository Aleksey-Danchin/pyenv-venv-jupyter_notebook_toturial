# Активация и деактивация окружения

> **Модуль 4 · Урок 3** | Время: ~10 мин

## Зачем активировать

После создания venv команды `python` и `pip` в терминале по-прежнему указывают на глобальный Python (системный или из pyenv). Чтобы использовать интерпретатор и пакеты **внутри** venv, окружение нужно **активировать**.

Активация — это настройка текущей сессии shell: изменение переменной `PATH` и добавление служебных переменных (об этом — в следующем уроке).

## Активация в Linux (bash/zsh)

В Linux и macOS виртуальное окружение активируется командой `source`:

```bash
source venv/bin/activate
```

Если вы назвали директорию иначе (например, `.venv`):

```bash
source .venv/bin/activate
```

Команда `source` выполняет скрипт в текущем shell, не запуская новый процесс. Скрипт `activate` настраивает переменные окружения для этой сессии.

**Ожидаемый результат:**

После активации в начале строки приглашения появляется префикс с именем окружения:

```
(venv) user@host:~/project$
```

Префикс `(venv)` показывает, что окружение активно. Теперь `python` и `pip` указывают на исполняемые файлы внутри venv.

## Деактивация

Чтобы вернуть shell в исходное состояние, выполните:

```bash
deactivate
```

Команда `deactivate` — это функция, которую добавляет скрипт `activate`. Она восстанавливает прежние значения `PATH` и удаляет переменную `VIRTUAL_ENV`.

**Ожидаемый результат:**

Префикс `(venv)` исчезает, приглашение возвращается к обычному виду:

```
user@host:~/project$
```

## Важно

- Активация действует **только в текущем терминале**. Открыв новый терминал, нужно активировать снова.
- В каждом новом окне/вкладке терминала — своя сессия: активация не переносится.
- Деактивация не удаляет venv — вы просто перестаёте его использовать в этой сессии.

## Частые ошибки

### Ошибка 1 — Путать синтаксис Windows и Linux

В Windows активация выполняется так: `venv\Scripts\activate`. В Linux — `source venv/bin/activate`. Курс ориентирован на Linux; используйте правильный путь для своей ОС.

### Ошибка 2 — Забывать деактивировать при смене проекта

Если вы переключаетесь между проектами в одном терминале и не деактивируете предыдущее окружение, `python` и `pip` могут указывать на venv другого проекта. Перед переходом к новому проекту выполните `deactivate`, затем активируйте нужный venv.

### Ошибка 3 — Выполнять `./venv/bin/activate`

Команда `./venv/bin/activate` запустит скрипт в отдельном процессе — изменения переменных не применятся к текущему shell. Нужно именно `source venv/bin/activate`.
