# Версия для текущей сессии

> **Модуль 2 · Урок 3** | Время: ~15 мин

## Зачем нужна сессионная версия

Иногда нужно **временно** переключить версию Python — протестировать код на другой версии, запустить скрипт, требующий конкретного интерпретатора, — без изменения глобальной или локальной настройки.

Команда `pyenv shell` устанавливает версию Python **только для текущей сессии терминала**. Закрыли терминал — настройка исчезла.

## Как установить сессионную версию

```bash
pyenv shell 3.13.0
```

Проверьте:

```bash
python --version
```

```
Python 3.13.0
```

Откройте **другой** терминал и проверьте версию там:

```bash
python --version
```

```
Python 3.12.0
```

Во втором терминале действует глобальная (или локальная) версия — `pyenv shell` повлиял только на тот терминал, где была выполнена команда.

## Как это работает: переменная `PYENV_VERSION`

**`PYENV_VERSION`** — переменная окружения, через которую pyenv задаёт сессионную версию Python. Она существует только в текущем процессе shell и его потомках.

Команда `pyenv shell 3.13.0` эквивалентна:

```bash
export PYENV_VERSION=3.13.0
```

Вы можете убедиться в этом:

```bash
pyenv shell 3.13.0
echo $PYENV_VERSION
```

```
3.13.0
```

При каждом вызове `python` pyenv первым делом проверяет, установлена ли переменная `PYENV_VERSION`. Если да — использует указанную в ней версию, игнорируя local и global.

## Сброс сессионной версии

Чтобы отменить `pyenv shell` и вернуться к обычному поведению (local → global → system):

```bash
pyenv shell --unset
```

Это удаляет переменную `PYENV_VERSION` из текущей сессии:

```bash
echo $PYENV_VERSION
```

```
(пусто)
```

Можно сбросить переменную и напрямую:

```bash
unset PYENV_VERSION
```

## Когда использовать `pyenv shell`

| Сценарий | Подходит? |
|----------|-----------|
| Быстро проверить код на другой версии Python | Да |
| Запустить одноразовый скрипт, требующий определённой версии | Да |
| Установить версию для проекта на постоянной основе | Нет — используйте `pyenv local` |
| Установить версию по умолчанию для всех терминалов | Нет — используйте `pyenv global` |

`pyenv shell` — инструмент для **экспериментов и одноразовых задач**. Для повседневной работы лучше подходят `pyenv local` и `pyenv global`.

## Частые ошибки

### Ошибка 1 — Ожидать, что shell-версия сохранится после закрытия терминала

Переменная `PYENV_VERSION` существует только в текущей сессии. Закрытие терминала уничтожает её. Если вам нужна постоянная привязка — используйте `pyenv local` или `pyenv global`.

### Ошибка 2 — Забыть сбросить shell-версию

Вы установили `pyenv shell 3.13.0` для теста, потом вернулись к работе над проектом, но pyenv продолжает использовать 3.13.0 вместо версии из `.python-version`. Проверьте:

```bash
pyenv version
```

```
3.13.0 (set by PYENV_VERSION environment variable)
```

Надпись `set by PYENV_VERSION` — верный признак того, что действует сессионная версия. Сбросьте её:

```bash
pyenv shell --unset
```

### Ошибка 3 — Установить PYENV_VERSION в `.bashrc`

Если добавить `export PYENV_VERSION=3.13.0` в файл `.bashrc`, эта переменная будет устанавливаться **в каждом новом терминале**, фактически превращая сессионную настройку в глобальную — причём с наивысшим приоритетом. Это заблокирует работу `pyenv local` и `pyenv global`. Никогда не прописывайте `PYENV_VERSION` в конфигурационных файлах shell.
