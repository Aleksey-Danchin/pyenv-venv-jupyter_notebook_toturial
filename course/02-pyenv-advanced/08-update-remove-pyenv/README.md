# Обновление и деинсталляция pyenv

> **Модуль 2 · Урок 6** | Время: ~15 мин

## Зачем обновлять pyenv

pyenv — активно развивающийся проект. Обновления добавляют поддержку **новых версий Python**. Если `pyenv install --list` не показывает нужную версию (например, только что вышедшую 3.14.0), скорее всего, нужно обновить pyenv.

## Обновление pyenv

pyenv, установленный через `curl https://pyenv.run | bash` (как в Модуле 1), — это git-репозиторий в `~/.pyenv`. Обновление сводится к `git pull`:

```bash
cd ~/.pyenv && git pull
```

```
Updating a1b2c3d..e4f5g6h
Fast-forward
 ...
```

После обновления проверьте:

```bash
pyenv --version
```

```
pyenv 2.5.0
```

Проверьте, появилась ли нужная версия Python:

```bash
pyenv install --list | grep "3.14"
```

### Обновление через pyenv-update

Если вместе с pyenv был установлен плагин `pyenv-update`, обновление ещё проще:

```bash
pyenv update
```

Эта команда обновляет и сам pyenv, и все установленные плагины. Проверить наличие плагина можно так:

```bash
ls ~/.pyenv/plugins/pyenv-update 2>/dev/null && echo "Плагин установлен" || echo "Плагин не установлен"
```

## Полная деинсталляция pyenv

Если вы решили полностью удалить pyenv из системы, процесс состоит из трёх шагов.

### Шаг 1 — Удалить строки инициализации из `.bashrc`

Откройте файл `~/.bashrc` в текстовом редакторе и удалите строки, добавленные при установке pyenv:

```bash
export PYENV_ROOT="$HOME/.pyenv"
[[ -d $PYENV_ROOT/bin ]] && export PATH="$PYENV_ROOT/bin:$PATH"
eval "$(pyenv init - bash)"
```

> Точный вид строк может отличаться в зависимости от версии pyenv. Ищите всё, что содержит `pyenv`.

### Шаг 2 — Удалить директорию `~/.pyenv`

```bash
rm -rf ~/.pyenv
```

Это удалит:
- сам pyenv
- **все установленные через pyenv версии Python**
- все плагины pyenv
- файл глобальной версии (`~/.pyenv/version`)
- все shims

### Шаг 3 — Перезагрузить shell

```bash
exec "$SHELL"
```

Или просто закройте и откройте терминал.

### Проверка

```bash
command -v pyenv
```

Если команда ничего не выводит — pyenv успешно удалён.

```bash
python3 --version
```

Теперь `python3` указывает на системный Python (если он установлен).

## Что остаётся после удаления pyenv

| Элемент | Удаляется? |
|---------|-----------|
| `~/.pyenv/` (pyenv + все версии Python) | Да (шаг 2) |
| Строки в `~/.bashrc` | Да (шаг 1, вручную) |
| Файлы `.python-version` в проектах | **Нет** — остаются, но без pyenv они безвредны |
| Системный Python | **Нет** — он не зависит от pyenv |

Файлы `.python-version`, оставшиеся в проектах, не вызовут ошибок: без pyenv они просто игнорируются. Но для чистоты можно удалить их вручную.

## Частые ошибки

### Ошибка 1 — Забыть удалить строки из `.bashrc`

Если удалить `~/.pyenv`, но оставить строки в `.bashrc`, при каждом запуске терминала будут появляться ошибки:

```
bash: /home/user/.pyenv/bin/pyenv: No such file or directory
```

Всегда начинайте деинсталляцию с очистки `.bashrc`.

### Ошибка 2 — Не осознавать, что удаление `~/.pyenv` уничтожает все версии Python

Директория `~/.pyenv/versions/` содержит все версии Python, установленные через pyenv. Удаление `~/.pyenv` удаляет их все. Если какие-то версии нужны — сначала убедитесь, что проекты могут работать с системным Python или переустановите нужные версии другим способом.

### Ошибка 3 — Обновлять pyenv через `apt`

pyenv **не устанавливается** через `apt` и не обновляется через `apt update`. Это git-репозиторий в домашней директории. Для обновления используйте `git pull` или `pyenv update`.
