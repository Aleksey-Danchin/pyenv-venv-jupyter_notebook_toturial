# Локальная версия для проекта

> **Модуль 2 · Урок 2** | Время: ~20 мин

## Зачем нужна локальная версия

Глобальная версия (`pyenv global`) действует на всю систему. Но на практике разные проекты требуют разных версий Python: один проект написан под 3.11, другой — под 3.12. Менять глобальную версию каждый раз при смене проекта — неудобно и чревато ошибками.

Команда `pyenv local` позволяет **привязать версию Python к конкретной директории**. Когда вы заходите в эту директорию (или любую её поддиректорию), pyenv автоматически переключается на указанную версию.

## Как установить локальную версию

Перейдите в директорию проекта и выполните:

```bash
cd ~/projects/my-app
pyenv local 3.11.7
```

Проверьте результат:

```bash
python --version
```

```
Python 3.11.7
```

Теперь выйдите из директории проекта и проверьте версию снова:

```bash
cd ~
python --version
```

```
Python 3.12.0
```

За пределами `~/projects/my-app` действует глобальная версия.

## Файл `.python-version`

Команда `pyenv local` создаёт файл `.python-version` в текущей директории:

```bash
cat ~/projects/my-app/.python-version
```

```
3.11.7
```

Это обычный текстовый файл с одной строкой — номером версии. Именно его pyenv ищет при каждом вызове `python`, поднимаясь по дереву директорий от текущей к корню.

## Наследование в поддиректориях

Файл `.python-version` действует на всю директорию **и все её поддиректории**:

```bash
cd ~/projects/my-app
python --version
# Python 3.11.7

cd ~/projects/my-app/src
python --version
# Python 3.11.7

cd ~/projects/my-app/tests
python --version
# Python 3.11.7
```

pyenv ищет файл `.python-version` начиная с текущей директории и поднимается вверх. Первый найденный файл определяет версию. Если ни в одной из родительских директорий файла нет — используется глобальная версия.

## Удаление локальной версии

Чтобы снять привязку версии к директории:

```bash
cd ~/projects/my-app
pyenv local --unset
```

Эта команда удаляет файл `.python-version`. После этого в директории снова действует глобальная версия.

Можно удалить файл и вручную:

```bash
rm .python-version
```

## `.python-version` и система контроля версий

Файл `.python-version` — важная часть конфигурации проекта. Он фиксирует, какую версию Python ожидает проект. Рекомендуется **добавлять его в git**, чтобы все участники команды работали с одной версией:

```bash
git add .python-version
git commit -m "Pin Python 3.11.7 for the project"
```

Когда коллега клонирует репозиторий и у него установлен pyenv, версия Python переключится автоматически при переходе в директорию проекта.

> Если у коллеги нет pyenv, файл `.python-version` просто игнорируется — он безвреден.

## Локальная версия перекрывает глобальную

Это ключевое правило:

```
local > global
```

Если в директории есть `.python-version`, pyenv использует указанную в нём версию, **игнорируя** глобальную настройку. Подробная схема приоритетов — в Уроке 4.

## Частые ошибки

### Ошибка 1 — Забыть добавить `.python-version` в git

Если файл не в репозитории, коллеги не узнают, какую версию Python ожидает проект. Они могут использовать другую версию и столкнуться с несовместимостью.

### Ошибка 2 — Установить local для версии, которой нет в pyenv

Как и с `pyenv global`, если указать несуществующую версию:

```bash
pyenv local 3.10.0
```

Файл `.python-version` будет создан, но при вызове `python`:

```
pyenv: version '3.10.0' is not installed (set by /home/user/projects/my-app/.python-version)
```

Ошибка подсказывает, какой файл задаёт версию — это помогает в диагностике.

### Ошибка 3 — Не понимать, что local перекрывает global

Типичная ситуация: вы изменили `pyenv global`, но в рабочей директории по-прежнему используется старая версия. Проверьте, нет ли файла `.python-version` в текущей или родительских директориях:

```bash
pyenv version
```

```
3.11.7 (set by /home/user/projects/my-app/.python-version)
```

Надпись `set by ... .python-version` указывает, что действует локальная настройка, а не глобальная.
