# Создание venv на базе конкретной версии Python (из pyenv)

> **Модуль 5 · Урок 1** | Время: ~15 мин

## Связка pyenv и venv

В модуле 4 вы научились создавать виртуальные окружения командой `python -m venv`. Но какой именно `python` используется? Ответ зависит от того, как настроен pyenv (модули 1–2).

Типичный рабочий поток:

1. **pyenv** выбирает версию Python для проекта (`pyenv local`, `.python-version`).
2. **venv** создаёт изолированное окружение пакетов на базе *этого* интерпретатора.

Без pyenv вы используете системный Python или тот, что первый попадётся в PATH. С pyenv вы явно фиксируете версию проекта.

## pyenv local перед созданием venv

Рекомендуемый порядок для нового проекта:

```bash
cd ~/projects/my-app
pyenv local 3.11.7
python -m venv venv
source venv/bin/activate
```

Команда `pyenv local 3.11.7` создаёт файл `.python-version` и заставляет `python` в этой директории указывать на Python 3.11.7 из pyenv. После этого `python -m venv venv` создаёт окружение на базе 3.11.7.

Проверить:

```bash
python --version
which python
```

**Ожидаемый результат:**

```
Python 3.11.7
/home/username/.pyenv/versions/3.11.7/bin/python
```

После активации venv `which python` покажет путь внутрь `venv/bin/`, но интерпретатор по-прежнему 3.11.7 — venv «запоминает» базовый Python при создании.

## Явное указание интерпретатора

Если pyenv не настроен для этой директории, можно указать интерпретатор напрямую:

```bash
~/.pyenv/versions/3.12.0/bin/python -m venv venv
```

Или для произвольной версии:

```bash
$(pyenv root)/versions/3.11.7/bin/python -m venv venv
```

Это полезно, когда вы хотите создать venv от конкретной версии, не меняя `pyenv local`.

## Что «запоминает» venv

Внутри venv в файле `pyvenv.cfg` записан путь к базовому Python:

```
home = /home/username/.pyenv/versions/3.11.7
include-system-site-packages = false
version = 3.11.7
```

Venv привязан к этому интерпретатору. Если удалить версию Python через `pyenv uninstall 3.11.7`, venv перестанет работать. Подробнее — в лабораторной-диагностике «сломанный venv».

## Сравнение с альтернативами

### venv vs conda environments

**Conda** — менеджер пакетов и окружений, объединяет управление версиями Python и библиотек. Окружения Conda: `conda create -n myenv python=3.11`, активация через `conda activate myenv`.

| Критерий | venv + pyenv | conda |
|----------|--------------|-------|
| Установка | Python встроен, pyenv отдельно | Требуется дистрибутив Anaconda/Miniconda |
| Изоляция | venv изолирует только пакеты, pyenv — версию Python | Conda изолирует и Python, и пакеты |
| Объём | Минимальный, без лишних пакетов | Conda-дистрибутивы обычно крупнее |
| Сценарий | Легковесные проекты, совместимость с системным Python | Data science, когда conda уже в стеке |

venv + pyenv — стандартный стек для большинства Python-проектов на Linux.

### venv vs poetry / pipenv

**Poetry** и **pipenv** — инструменты «всё в одном»: создание окружения, управление зависимостями, lock-файлы. Используют venv под капотом, но добавляют свой формат (pyproject.toml, Pipfile).

| Критерий | venv + pip | poetry / pipenv |
|----------|------------|-----------------|
| Сложность | Просто: venv + requirements.txt | Дополнительный инструмент, свой формат |
| Совместимость | Максимальная — стандартный pip | Зависимость от экосистемы инструмента |
| Lock-файлы | pip freeze вручную | Автоматические (poetry.lock, Pipfile.lock) |

venv + pip — базовый уровень; poetry/pipenv — когда нужны lock-файлы и единый workflow без ручного freeze.

## Частые ошибки

### Ошибка 1 — Создавать venv до pyenv local

Если не выполнить `pyenv local` до `python -m venv`, будет использоваться глобальная или системная версия Python. Проект может «случайно» получить Python 3.10 вместо 3.12.

Всегда: сначала `pyenv local <version>`, затем `python -m venv venv`.

### Ошибка 2 — Не понимать, что venv «запоминает» базовый Python

Venv создаётся от того Python, который вызвал `python -m venv`. После создания смена `pyenv local` на другую версию не меняет уже созданный venv — он продолжает ссылаться на старый интерпретатор. Чтобы сменить версию, нужно пересоздать venv.

### Ошибка 3 — Создавать venv в неправильной директории

Venv — это просто директория. Создавайте её в корне проекта (например, `venv` или `.venv`), а не в родительских каталогах. Так `.gitignore` и навигация остаются предсказуемыми.
