# Удаление окружения

> **Модуль 5 · Урок 5** | Время: ~10 мин

## Venv — это директория

Виртуальное окружение — не «установленная программа». Это обычная директория с файлами: `bin/`, `lib/`, `pyvenv.cfg`. Удаление venv = удаление этой директории.

Специальной команды для «деинсталляции» venv нет.

## Корректный порядок удаления

1. **Деактивировать** окружение, если оно активировано:

```bash
deactivate
```

Иначе переменные окружения и PATH будут ссылаться на уже несуществующие пути — возможны ошибки в текущей сессии.

2. **Удалить директорию**:

```bash
rm -rf venv/
```

Если venv называется `.venv`:

```bash
rm -rf .venv/
```

## Почему важна деактивация

Если удалить venv, не выполнив `deactivate`:

- `echo $VIRTUAL_ENV` покажет путь к удалённой директории.
- Команды `python` и `pip` могут вести к несуществующим бинарникам.
- В новом терминале проблема исчезнет, но в текущем — будет путаница.

Привычка: перед `rm -rf venv` всегда выполнять `deactivate`.

## Что остаётся после удаления venv

- Файл `.python-version` (если использовался pyenv) — не трогается.
- `requirements.txt` — остаётся в проекте.
- Системный Python и пакеты в нём — без изменений.

Чтобы заново поднять окружение: `python -m venv venv`, `source venv/bin/activate`, `pip install -r requirements.txt`.

## Частые ошибки

### Ошибка 1 — Искать команду «удалить venv»

Команды типа `venv --remove` или `pip uninstall venv` не существуют. Удаление — это `rm -rf` директории.

### Ошибка 2 — Удалять без деактивации

Текущий shell будет ссылаться на удалённые файлы. Выполняйте `deactivate` перед удалением.

### Ошибка 3 — Путать удаление venv с удалением версии Python

`pyenv uninstall 3.11.7` удаляет сам интерпретатор. Venv, созданный от этой версии, после этого перестанет работать (см. лабораторную-диагностику «сломанный venv»). Удаление venv не трогает pyenv.
