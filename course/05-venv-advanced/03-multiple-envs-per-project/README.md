# Несколько окружений для одного проекта

> **Модуль 5 · Урок 3** | Время: ~15 мин

## Когда нужны несколько venv

Обычно один проект — одно виртуальное окружение. Но иногда целесообразно иметь несколько:

| Сценарий | Пример |
|----------|--------|
| Разделение dev и prod | Разные версии пакетов: в dev — инструменты тестирования, в prod — только runtime. |
| Тестирование на разных версиях Python | Проект должен работать на 3.10 и 3.12 — отдельные venv для проверки. |
| Разные наборы зависимостей | Один venv для backend, другой для скриптов обработки данных. |

## Именование и структура

Часто используются имена вроде:

- `.venv` или `venv` — основное окружение.
- `.venv-dev`, `venv-dev` — окружение разработки (pytest, black, mypy).
- `.venv-prod` — минимальное окружение для продакшена.
- `venv-py311`, `venv-py312` — окружения под разные версии Python.

Пример:

```bash
cd ~/projects/my-app
pyenv local 3.11.7
python -m venv venv
python -m venv venv-dev
source venv-dev/bin/activate
pip install pytest black mypy
```

## Работа с несколькими окружениями

В каждый момент времени активно только одно окружение (то, которое активировано через `source`). При переключении между задачами:

```bash
deactivate
source venv-dev/bin/activate
# работа с инструментами разработки
deactivate
source venv/bin/activate
# работа с основным кодом
```

Убедиться, какое окружение активно: `echo $VIRTUAL_ENV` или по префиксу в prompt.

## Когда не нужно создавать множество venv

Не создавайте лишние окружения «на всякий случай». Один venv с полным набором зависимостей (включая dev) обычно достаточен. Отдельные venv под разные версии Python — только если вы реально проверяете совместимость.

## Частые ошибки

### Ошибка 1 — Создавать множество venv без необходимости

Каждое окружение занимает место и требует обновления. Сначала убедитесь, что один venv действительно не подходит.

### Ошибка 2 — Путать, какое окружение активировано

Работаете с `venv-dev`, а думаете, что в `venv`. Проверяйте `echo $VIRTUAL_ENV` или prompt. При сомнении — `deactivate` и заново `source` нужного окружения.

### Ошибка 3 — Забывать обновлять все окружения

Если в проекте несколько venv и вы обновили зависимости в одном — не забудьте синхронизировать остальные (через `requirements.txt` и `pip install -r`).
