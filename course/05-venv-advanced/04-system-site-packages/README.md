# --system-site-packages — когда нужен доступ к системным пакетам

> **Модуль 5 · Урок 4** | Время: ~15 мин

## Поведение venv по умолчанию

По умолчанию venv создаёт полностью изолированное окружение: пакеты из системного Python (или из site-packages базового интерпретатора pyenv) *не видны* внутри venv. Вы устанавливаете только то, что нужно проекту.

## Что делает --system-site-packages

Флаг `--system-site-packages` разрешает venv *видеть* пакеты из site-packages базового Python:

```bash
python -m venv --system-site-packages venv
```

После активации такого venv команда `import some_package` может найти пакет, установленный в базовом Python, даже если вы не ставили его через pip внутри venv.

## Когда это может понадобиться

Редкие случаи:

| Ситуация | Пояснение |
|----------|-----------|
| Системные биндинги | Некоторые библиотеки (например, для работы с драйверами) устанавливаются через системный пакетный менеджер и ожидаются в системном Python. |
| Ограничения окружения | В некоторых средах нельзя устанавливать пакеты в venv, но системные пакеты доступны. |
| Наследование | Нужно дополнить существующую системную установку несколькими пакетами проекта. |

В обычной разработке такой флаг обычно *не* нужен.

## Почему по умолчанию не использовать

При `--system-site-packages`:

- Неясно, откуда берётся пакет — из venv или из системы.
- Версии могут конфликтовать.
- Воспроизводимость окружения падает: на другой машине может не быть нужных системных пакетов.
- pip внутри venv может ставить пакеты в системный site-packages при определённых условиях — это источник путаницы и багов.

Подробнее о проблеме «pip внутри venv указывает на системный» — в лабораторной-диагностике (юнит 08).

## Проверка: использует ли venv системные пакеты

В файле `pyvenv.cfg` внутри venv найдите строку:

```
include-system-site-packages = true
```

Если `true` — venv создан с `--system-site-packages`.

## Частые ошибки

### Ошибка 1 — Использовать --system-site-packages «на всякий случай»

Это увеличивает риски конфликтов и неопределённости. Используйте только при явной необходимости.

### Ошибка 2 — Не понимать риски смешивания

С системными пакетами сложнее предсказать, какая версия будет импортирована. При проблемах с зависимостями первым шагом попробуйте пересоздать venv без флага.

### Ошибка 3 — Думать, что флаг решает проблему «пакет не найден»

Если пакет не устанавливается в venv, причина чаще в другом (неверный pip, не активирован venv, проблема с PATH). `--system-site-packages` — не универсальное решение.
