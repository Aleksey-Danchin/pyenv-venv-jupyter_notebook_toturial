# Лабораторная-диагностика: сломанный venv (удалена версия Python из pyenv)

> **Модуль 5 · Диагностика** | Время: ~15 мин

## Сценарий

Вы или коллега создали виртуальное окружение от конкретной версии Python (управляемой pyenv). Позже эту версию удалили командой `pyenv uninstall`. Теперь при попытке использовать venv — ошибка: Python не найден.

Ваша задача — воспроизвести проблему, понять причину и восстановить работоспособность.

## Воспроизведение проблемы

Запустите скрипт, создающий «сломанное» состояние:

```bash
bash break.sh
```

Скрипт установит временную версию Python, создаст venv, затем удалит эту версию. Окружение останется «осиротевшим».

## Симптомы

После запуска `break.sh`:

1. Перейдите в директорию проекта и попробуйте активировать окружение:
   ```bash
   cd ~/course-debug-broken-venv
   source venv/bin/activate
   ```

2. Или запустите Python напрямую:
   ```bash
   ~/course-debug-broken-venv/venv/bin/python --version
   ```

Вы увидите ошибку вроде:

```
bash: .../venv/bin/python: No such file or directory
```

или при активации — сообщение о том, что интерпретатор не найден. В файле `venv/pyvenv.cfg` указан путь к удалённой версии Python.

## Задание

1. Убедитесь, что venv «сломан» — интерпретатор недоступен.
2. Определите причину (проверьте `venv/pyvenv.cfg`, путь к базовому Python).
3. Восстановите работоспособность: установите нужную версию Python через pyenv и при необходимости пересоздайте venv.

## Подсказка 1

<details><summary>Показать подсказку</summary>

Прочитайте `venv/pyvenv.cfg`. В нём указан путь к базовому (home) Python. Проверьте, существует ли этот путь: `ls` по указанной директории.

</details>

## Подсказка 2

<details><summary>Показать подсказку</summary>

Базовый Python был удалён через `pyenv uninstall`. Симлинки внутри venv указывают на несуществующий путь. Решение: снова установить ту же версию Python через `pyenv install <version>`. После этого venv сможет использовать восстановленный интерпретатор.

</details>

## Подсказка 3

<details><summary>Показать подсказку</summary>

Скрипт использует версию 3.11.7 (или указанную в скрипте). Выполните `pyenv install 3.11.7` (или нужную версию), затем проверьте: `source venv/bin/activate` и `python --version`. Если venv был создан от этой версии, он должен заработать после повторной установки.

</details>

## Самопроверка

```bash
cd ~/course-debug-broken-venv
source venv/bin/activate
python --version
pip list
deactivate
```

**Ожидаемый результат:** активация проходит без ошибок, `python --version` показывает версию, `pip list` выводит список пакетов (может быть пустым).
