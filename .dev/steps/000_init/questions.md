## Ответ методиста на вопрос 2.8 (утилиты для скриншотов и GIF)

> **Рекомендация методиста:**
>
> Для работы в Kubuntu в связке с AI-агентом оптимальный набор:
>
> | Задача | Утилита | Почему |
> |--------|---------|--------|
> | Скриншоты с маркерами | **flameshot** | CLI-интерфейс (`flameshot full -p ./path/`), можно вызвать из скрипта или по инструкции агента. Поддерживает аннотации (стрелки, рамки, текст) через GUI. |
> | Скриншоты терминала (текстовые) | Копирование вывода + вставка в markdown-блок ```` ```bash ```` | Для команд терминала скриншот часто избыточен — текстовый вывод удобнее, доступнее и легче поддерживать. |
> | GIF-запись экрана | **peek** | Простой GUI, записывает область экрана прямо в GIF. Агент может дать инструкцию: «Запиши GIF выполнения следующих шагов». |
> | Конвертация видео → GIF | **ffmpeg** | CLI-утилита, агент может сформировать точную команду конвертации. |
>
> **Принцип:** где возможно — текстовый вывод вместо скриншотов (проще поддерживать, доступнее). Скриншоты и GIF — для GUI-действий (Jupyter в браузере, настройки KDE и т.п.).
>
> Установка одной командой:
> ```bash
> sudo apt install flameshot peek ffmpeg
> ```

## Ответ методиста на вопрос 2.6 (лабораторные с заложенными ошибками)

> Отличная идея. Предлагаю формат **«Лабораторная-диагностика»**:
> 1. Студент получает описание ситуации («коллега настроил окружение, но Jupyter не запускается»)
> 2. Предоставляется воспроизводимый сценарий (скрипт, создающий «сломанное» состояние)
> 3. Задача: найти и исправить ошибку
> 4. Подсказки с нарастающей детализацией (спойлер-блоки в markdown)
> 5. Эталонное решение — в отдельном файле
>
> Такие лабораторные будут помечены в названии файла, например: `05-lab-debug-broken-kernel.md`

### Принятые уточнения

1. **Практика:** обеспечить достаточно заданий для закрепления. Лабораторные и тесты «снежным комом» после каждых 2–3 уроков.
2. **Формат обсуждения:** создать отдельный Cursor rule, закрепляющий формат «раунды вопросов → файл → варианты ответов → графа Ответ → нумерация».
3. **Rules детализация:** разбить на несколько файлов с globs — для уроков, лабораторных, тестов, cheatsheets. Каждое правило применяется только к своему типу файлов.
4. **Pre-made Jupyter notebooks:** в модуле 8 (Jupyter: практикум) использовать готовые `.ipynb` файлы с начальным контентом — графики, примеры Python-кода, демонстрация возможностей.
5. **Терминология:** курс не боится терминов. Первое появление — определение + запись в глоссарий. Дальше — термин без пояснений, со сноской на глоссарий.
6. **Git в Проектной практике:** базовые команды git, создание репозитория на GitHub — без углубления, с пометкой «это не курс по git».
7. **Модуль «Jupyter: практикум»:** отдельный модуль для набивания руки — работа с готовыми ноутбуками, практические задачи.
