## Обсуждение: формат команды для создания модулей

### Контекст

Нужна переиспользуемая «команда» для создания учебного материала модуля. Сценарий: пользователь вызывает команду, указывает номер модуля — агент создаёт все юниты этого модуля по плану.

### Варианты

| # | Вариант | Как вызывается | Плюсы | Минусы |
|---|---------|---------------|-------|--------|
| A | **Cursor Rule** (`.cursor/rules/*.mdc`) | Автоматически по globs или `alwaysApply: true` | Знакомый формат, уже используем | Нельзя «вызвать» по запросу. Либо применяется всегда (тратит контекст), либо по глобу (нет подходящего паттерна для «создания модуля»). Лимит ~50 строк |
| B | **Skill** (`.cursor/skills/*/SKILL.md`) | Агент подхватывает автоматически по описанию, или пользователь ссылается явно | Создан для сложных workflow. Поддерживает вложенные файлы (reference.md, examples). До 500 строк. Может содержать пошаговый алгоритм | Нужно создать директорию со структурой |
| C | **Файл-промпт** (`.dev/prompts/create-module.md`) | Пользователь пишет: `@.dev/prompts/create-module.md Модуль 0` | Максимально просто. Полный контроль. Никакой магии | Нет автоматического обнаружения. Просто текстовый файл без метаданных |

### Рекомендация методиста

**Вариант B — Skill.** Причины:

1. **Задача сложная и многошаговая** — создание модуля включает: чтение программы, создание директорий, написание 4–9 юнитов разных типов, навигацию, обновление глоссария, cheatsheets, `course/README.md`. Это именно тот случай, для которого скиллы созданы.

2. **Скилл поддерживает progressive disclosure** — основной `SKILL.md` (алгоритм работы, до 500 строк) + вложенные файлы для справки (шаблоны, примеры). Агент читает `SKILL.md` → понимает, что делать → при необходимости читает детали из вложенных файлов.

3. **Автоматическое обнаружение** — если в описании скилла написать «Use when creating course modules» — агент подхватит его, когда пользователь скажет «создай модуль 3». Не нужно помнить путь к файлу.

4. **Явный вызов тоже работает** — можно написать `@.cursor/skills/create-module/SKILL.md Модуль 0` для полной определённости.

5. **Правила (Rules) уже работают параллельно** — при создании файлов в `course/**/*lab*/**` автоматически подключится `course-labs.mdc`, при работе с `course/**/README.md` — `course-lessons.mdc`. Скилл управляет процессом, правила проверяют формат. Разделение ответственности.

### Результат: скилл создан

Создан `.cursor/skills/create-module/` со следующей структурой:

```
.cursor/skills/create-module/
├── SKILL.md       # Алгоритм из 4 фаз: подготовка → планирование → написание → финализация
└── reference.md   # Шаблоны всех 6 типов юнитов + чеклист модуля
```

**Как использовать:** начать новый чат и написать `Создай модуль 0` (или `@.cursor/skills/create-module/SKILL.md Модуль 0` для явности). Агент прочитает скилл, программу курса, конвенции — и создаст все юниты модуля.

**Что содержит SKILL.md (~120 строк):**
- Фаза 1: подготовка — чтение программы, конвенций, проверка предпосылок (скелет, глоссарий, cheatsheets)
- Фаза 2: планирование — именование директорий, определение файлов, навигационные ссылки
- Фаза 3: написание — последовательное создание юнитов, обновление справочников
- Фаза 4: финализация — обновление оглавления, проверка навигации, чеклист
- Правила: язык, терминология, вставки-сравнения, «Частые ошибки», снежный ком
- Обработка комбинированных юнитов: «Урок + тренажёр» → один юнит-тренажёр, «Тест / Лабораторная» → два юнита

**Что содержит reference.md (~250 строк):**
- Шаблоны README.md для всех 6 типов юнитов
- Шаблоны solution.md, check.sh, break.sh
- Таблица именования директорий
- Чеклист модуля: структура, навигация, контент, справочники, качество
