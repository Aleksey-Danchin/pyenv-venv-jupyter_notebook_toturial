
**Важно (по программе и conventions):** это не курс по git. Базовые команды даются для контекста — достаточно для публикации проекта. В материалах явно указывается это ограничение.

## Тезисный план юнитов

### 01 — Структура Python-проекта: что где лежит (Урок)

- **Цель:** показать типовую структуру Python-проекта и назначение директорий/файлов.
- **Ключевые понятия:** структура проекта, `src/`, `tests/`, корневая директория.
- **Содержание:** типовые папки (src, tests, docs, scripts); `.python-version`, `requirements.txt`; где хранить код, тесты, конфиги.
- **Частые ошибки:** свалить всё в корень; не различать production и dev-зависимости.
- **Опирается на:** модули 2–5 (pyenv local, venv, requirements), модуль 6–9 (Jupyter).
- **Подготавливает:** 02, 03.

### 02 — .gitignore для Python-проектов (Урок)

- **Цель:** научить исключать из репозитория venv, кеш, чекпоинты и др.
- **Ключевые понятия:** .gitignore, шаблон для Python.
- **Содержание:** venv/, `__pycache__/`, `.ipynb_checkpoints/`, `.env`, `*.pyc`, `dist/`, `build/`; типовой шаблон для Python.
- **Частые ошибки:** коммитить venv; забыть .ipynb_checkpoints.
- **Опирается на:** 01. **Подготавливает:** 04, 06.

### 03 — requirements.txt vs requirements-dev.txt (Урок)

- **Цель:** разделить production- и dev-зависимости.
- **Ключевые понятия:** requirements.txt, requirements-dev.txt, разделение окружений.
- **Содержание:** что в production (приложение, библиотеки); что в dev (pytest, black, jupyter, ipykernel); как устанавливать: `pip install -r requirements.txt` и отдельно dev.
- **Частые ошибки:** смешивать всё в одном файле; не документировать dev-зависимости.
- **Опирается на:** модуль 3 (pip, requirements), модуль 5 (requirements в venv), 01.
- **Подготавливает:** 06.

### 04 — Базовый git: init, add, commit, push, GitHub (Урок)

- **Цель:** дать минимум для инициализации репозитория и публикации на GitHub.
- **Ключевые команды:** `git init`, `git add`, `git status`, `git commit`, `git remote add`, `git push`.
- **Содержание:** создание репозитория; первый коммит; подключение remote; создание репо на GitHub (кратко); push.
- **Ограничение:** явно указать, что это не курс по git — только контекст для публикации проекта.
- **Частые ошибки:** коммитить без .gitignore; забыть про remote до push.
- **Опирается на:** 01, 02, 03. **Подготавливает:** тест и лабораторную.

### 05 — Тест: организация проекта (Тест)

- **Охватывает:** уроки 01–04 (структура, .gitignore, requirements/dev, базовый git).
- **Принцип «снежного кома»:** включает вопросы по модулям 2–5 (pyenv, venv, pip), 6–9 (Jupyter) в контексте организации проекта.
- **Формат:** ~10 вопросов с вариантами ответов.

### 06 — Лабораторная: организация проекта (Лабораторная)

- **Задание:** создать проект с нуля по лучшим практикам: структура, .gitignore, requirements.txt (+ requirements-dev.txt), git init, первый коммит, push на GitHub (или локально).
- **Снежный ком:** pyenv local, venv, pip install, возможно jupyter/ipykernel — в зависимости от задания.
- **Файлы:** `README.md`, `solution.md`, `check.sh`.
- **Подсказки:** 3 уровня нарастающей детализации.
