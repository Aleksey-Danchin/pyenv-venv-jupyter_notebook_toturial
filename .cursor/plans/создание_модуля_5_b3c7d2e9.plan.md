## Тезисный план юнитов

### 01 — Создание venv на базе конкретной версии Python (из pyenv) (Урок)

- **Цель:** научиться создавать venv от конкретной версии Python, управляемой pyenv.
- **Ключевые команды:** `pyenv versions`, `~/.pyenv/versions/<ver>/bin/python -m venv`, `python -m venv` (при pyenv local).
- **Содержание:** pyenv local → python; явное указание интерпретатора; связка pyenv + venv.
- **Вставка-сравнение:** venv vs conda environments · venv vs poetry/pipenv (краткие вставки по программе).
- **Частые ошибки:** создавать venv до pyenv local; не понимать, что venv «запоминает» базовый Python.
- **Опирается на:** модуль 2 (pyenv local), модуль 4 (создание venv).

### 02 — requirements.txt в контексте venv — создание и воспроизведение (Урок)

- **Цель:** освоить workflow freeze → requirements.txt → воспроизведение окружения в venv.
- **Ключевые команды:** `pip freeze`, `pip install -r requirements.txt`.
- **Содержание:** активация venv → pip install → pip freeze > requirements.txt; воспроизведение на другой машине/проекте.
- **Частые ошибки:** freeze без активации venv; забывать .python-version для воспроизведения версии Python.
- **Опирается на:** модуль 3 (pip freeze, requirements), модуль 4 (pip в venv). **Подготавливает:** лабы и модуль 11.

### 03 — Несколько окружений для одного проекта (Урок)

- **Цель:** показать сценарии, когда нужны несколько venv в одном проекте.
- **Ключевые понятия:** dev/prod-окружения, окружения под разные версии Python для тестирования.
- **Содержание:** структура `.venv-dev`, `.venv-prod`, `venv-py311`, `venv-py312`; когда это оправдано.
- **Частые ошибки:** создавать множество venv без нужды; путать, какое окружение активировано.
- **Опирается на:** 01, 02. **Подготавливает:** тест и лабораторную.

### 04 — --system-site-packages — когда нужен доступ к системным пакетам (Урок)

- **Цель:** объяснить флаг `--system-site-packages` и редкие сценарии его применения.
- **Ключевые команды:** `python -m venv --system-site-packages <dir>`.
- **Содержание:** что делает флаг; когда нужен (системные биндинги, драйверы); почему по умолчанию не использовать.
- **Частые ошибки:** использовать «на всякий случай»; не понимать риски смешивания.
- **Опирается на:** модуль 4 (структура venv). **Подготавливает:** диагностику pip→системный.

### 05 — Удаление окружения (Урок)

- **Цель:** научиться корректно удалять venv.
- **Ключевая мысль:** venv — это просто директория; удаление = `rm -rf venv/`.
- **Содержание:** деактивация перед удалением; что удалять; почему не нужна специальная команда.
- **Частые ошибки:** пытаться «деинсталлировать» venv; удалять без деактивации (риски).
- **Опирается на:** модуль 4. **Подготавливает:** диагностику сломанного venv.

### 06 — Тест: venv + pyenv, requirements, множественные окружения (Тест)

- **Охватывает:** уроки 01–05 (venv от pyenv, requirements, несколько окружений, --system-site-packages, удаление).
- **Принцип «снежного кома»:** вопросы по модулям 3–4 (pip, freeze, активация venv).
- **Формат:** ~10–12 вопросов с вариантами ответов.

### 07 — Лабораторная: venv + pyenv, requirements, множественные окружения (Лабораторная)

- **Задание:** pyenv local → создать venv → установить пакеты → freeze → воспроизвести в новом venv; опционально несколько окружений.
- **Снежный ком:** pyenv, pip, .python-version.
- **Файлы:** `README.md`, `solution.md`, `check.sh`.

### 08 — Лабораторная-диагностика: pip внутри venv указывает на системный (Лабораторная-диагностика)

- **Цель:** воспроизвести ситуацию, когда pip в «активном» venv ставит пакеты в системный Python.
- **break.sh:** создаёт venv с --system-site-packages или симулирует поломку (например, битый activate).
- **Задание:** обнаружить, что pip ставит не туда; исправить (пересоздать venv без флага и т.п.).
- **Файлы:** `README.md`, `break.sh`, `solution.md`.
- **Краевой случай #3** (по программе).

### 09 — Лабораторная-диагностика: сломанный venv (удалена версия Python из pyenv) (Лабораторная-диагностика)

- **Цель:** отработать ситуацию, когда venv указывает на удалённую версию Python.
- **break.sh:** создаёт venv от конкретной версии, затем pyenv uninstall этой версии.
- **Задание:** понять причину ошибки; пересоздать venv от актуальной версии.
- **Файлы:** `README.md`, `break.sh`, `solution.md`.
- **Краевой случай #6** (по программе).
