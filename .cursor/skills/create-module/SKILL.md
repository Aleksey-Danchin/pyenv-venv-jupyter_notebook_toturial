# Создание модуля курса

## Входные данные

Пользователь указывает **номер модуля** (0–11). Вся информация о модуле берётся из программы курса.

## Алгоритм

### Фаза 1 — Подготовка

1. **Прочитать программу курса** — `docs/course-program.md`. Найти секцию нужного модуля: цель, таблицу юнитов (номер, название, тип), вставки-сравнения.

2. **Прочитать конвенции** — `docs/conventions.md`. Освежить правила именования, навигации, терминологии, медиаданных.

3. **Определить директорию модуля** по таблице:

   | Модуль | Директория |
   |--------|-----------|
   | 0 | `course/00-python-environment/` |
   | 1 | `course/01-pyenv-basics/` |
   | 2 | `course/02-pyenv-advanced/` |
   | 3 | `course/03-pip/` |
   | 4 | `course/04-venv-basics/` |
   | 5 | `course/05-venv-advanced/` |
   | 6 | `course/06-jupyter-notebook/` |
   | 7 | `course/07-jupyter-kernels/` |
   | 8 | `course/08-jupyter-practice/` |
   | 9 | `course/09-jupyterlab/` |
   | 10 | `course/10-project-practice/` |
   | 11 | `course/11-integration/` |

4. **Проверить предпосылки:**
   - Существует ли `course/README.md` (оглавление)? Если нет — создать скелет.
   - Существуют ли `course/references/glossary.md` и `course/references/terminal-commands.md`? Если нет — создать по шаблону из `.cursor/rules/course-references.mdc`.
   - Существуют ли файлы cheatsheets? Если нет и модуль их требует — создать скелеты.
   - Для модулей 1+ : проверить, что предыдущий модуль существует (для навигационных ссылок).

5. **Прочитать глоссарий** (`course/references/glossary.md`) — чтобы знать, какие термины уже определены и не дублировать определения.

6. **Прочитать существующие cheatsheets** — чтобы знать, какие команды уже зафиксированы.

### Фаза 2 — Планирование юнитов

Для каждого юнита из таблицы программы определить:

1. **Имя директории** по конвенции:
   - Урок: `NN-краткое-имя/` (например, `01-system-python/`)
   - Тренажёр: `NN-trainer-краткое-имя/` (например, `02-trainer-installation/`)
   - Лабораторная: `NN-lab-краткое-имя/` (например, `05-lab-install-and-switch/`)
   - Лабораторная-диагностика: `NN-lab-debug-краткое-имя/` (например, `06-lab-debug-missing-python/`)
   - Тест: `NN-test-краткое-имя/` (например, `05-test-versions/`)

2. **Файлы юнита** по типу:
   - Урок → `README.md`
   - Тренажёр → `README.md`, `check.sh`
   - Лабораторная → `README.md`, `solution.md`, `check.sh`
   - Лабораторная-диагностика → `README.md`, `break.sh`, `solution.md`
   - Тест → `README.md`
   - Практика с .ipynb → `README.md`, `practice-*.ipynb`

3. **Тезисный план каждого юнита** — для каждого юнита кратко описать:
   - Главная мысль / цель юнита (1 предложение)
   - Ключевые понятия или команды, которые будут введены
   - Особенности: вставка-сравнение, практический эксперимент, специфика задания (для лабораторных/тестов)
   - Связь с предыдущими/следующими юнитами (на что опирается, что подготавливает)

   Этот план показать пользователю **перед** началом написания контента для согласования.

4. **Навигационные ссылки** — для каждого юнита определить предыдущий и следующий:
   - Первый юнит модуля: `← Назад` → `../README.md` (обложка модуля)
   - Последний юнит модуля: `Далее →` → `../README.md` (обложка модуля, секция «Итоги модуля»)
   - Между юнитами: ссылки на соседние юниты внутри модуля

   **ВАЖНО: формат ссылок.** Все ссылки должны указывать на `README.md` явно, а не на директорию. Это обеспечивает работу ссылок и на GitHub, и в IDE.
   - Правильно: `../02-path-resolution/README.md`
   - Неправильно: `../02-path-resolution/`

### Фаза 2.5 — README модуля (обложка)

Перед написанием юнитов создать `README.md` в корне директории модуля — обложку модуля. Это НЕ учебный юнит, а лэндинг-страница. Шаблон — в [reference.md](reference.md), правило — `.cursor/rules/course-module-readme.mdc`.

Обложка содержит:
- **Начало:** «Чему вы научитесь», «Что будет рассмотрено», «Инструменты и команды», таблица юнитов со ссылками.
- **Конец:** «Итоги модуля» (резюме), «Чеклист навыков» (`- [ ]`), «Ключевые команды».

Навигация в обложке — между модулями (не юнитами): `← Предыдущий модуль | Оглавление | Следующий модуль →`.

### Фаза 3 — Написание контента

Создавать юниты **последовательно**, от первого к последнему. Для каждого юнита:

1. **Создать директорию** юнита.
2. **Написать `README.md`** по шаблону типа (см. [reference.md](reference.md) и правила в `.cursor/rules/`).
3. **Написать вспомогательные файлы** (`solution.md`, `check.sh`, `break.sh`) если тип юнита их требует.
4. **Обновить справочники** при необходимости:
   - Новый термин → определение в тексте + запись в `course/references/glossary.md`
   - Новая команда терминала → справка в тексте + запись в `course/references/terminal-commands.md`
   - Новая команда инструмента → запись в соответствующий cheatsheet

### Фаза 4 — Финализация модуля

1. **Создать `summary.md`** — конспект модуля. Тезисная выжимка для печати: ключевые понятия, команды, типичные ошибки, схема (если уместно). Шаблон — в [reference.md](reference.md), правило — `.cursor/rules/course-summary.mdc`.
2. **Обновить README модуля** — заполнить секцию «Итоги модуля» (резюме, чеклист навыков, ключевые команды) на основе написанного контента.
3. **Обновить `course/README.md`** — добавить/обновить секцию модуля со ссылками на все юниты.
4. **Проверить навигацию** — убедиться, что все ссылки `← Назад`, `Оглавление`, `Далее →` корректны.
5. **Проверить по чеклисту** (см. [reference.md](reference.md)).

## Правила написания контента

### Язык и стиль

- **Весь контент на русском языке.**
- Обращение к студенту на «вы» (но без излишней формальности).
- Тон: уверенный, профессиональный, без «воды».
- Примеры — реальные, а не абстрактные.

### Терминология

- Первое появление термина в курсе → **определение прямо в тексте** + запись в глоссарий.
- Если термин уже определён в предыдущем модуле → использовать свободно, со сноской `[^глоссарий]` или ссылкой.
- Никогда не переопределять ранее введённый термин.

### Терминальные команды

- Вывод терминала — в блоке ` ```bash ``` `, не скриншотами.
- При первом появлении команды — справка 1–2 предложения.
- Добавить в `course/references/terminal-commands.md`.

### Вставки-сравнения

- Если программа указывает `Вставки-сравнения` для модуля — добавить секцию `## Сравнение с альтернативами` в соответствующий урок.
- Краткая вставка, не отдельный юнит.

### Секция «Частые ошибки»

- **Обязательна в каждом уроке** (тип «Урок»).
- 2–4 типичных ошибки с объяснением, почему это ошибка и как избежать.

### Принцип «снежного кома»

- Тесты и лабораторные включают вопросы/задания не только по новым урокам, но и по ранее пройденным в этом модуле.

### Юниты-комбинации

Некоторые юниты в программе отмечены как «Урок + тренажёр» или «Тест / Лабораторная». Обработка:

- **«Урок + тренажёр»** — создать **один** юнит. Директория по типу тренажёра (`NN-trainer-*`). Содержание: теоретическая часть + пошаговое выполнение. Файлы: `README.md`, `check.sh`.
- **«Тест / Лабораторная»** — создать **два** юнита: отдельный тест (`NN-test-*`) и отдельную лабораторную (`(NN+1)-lab-*`). Номера идут последовательно. Это означает, что реальное число юнитов может быть больше, чем в таблице программы.
